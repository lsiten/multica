从收件箱旁的**应用**进入面板，按项目查看应用、按运行时查看部署位置，或在运行看板关注状态。项目和运行时详情也提供应用入口。服务在选定运行时的机器上执行，Multica 负责控制、状态同步和远程访问。

## 应用与实例

**服务应用**运行实际进程。托管服务配置项目资源、工作目录、准备命令、启动程序与参数、环境变量，以及可选端口和健康检查。接入已有服务只连接本地端口，不接管它的进程。

**组合应用**包含服务或其他组合，自身不启动进程。一个项目可以有多个独立服务和组合。配置按版本保存；保存修改不会改变正在运行的实例，需要明确重启才能应用新版本。

**运行实例**对应一个应用在一个运行时上的执行对象。同一应用有多个实例时，操作前选择运行时。关闭页面或结束创建应用的智能体运行不会自动停止服务。

## 关系与运行位置

关系限定在同一项目：

- `contains`：包含服务或嵌套组合。
- `depends_on`：等待依赖已启动或健康。必需依赖失败会阻塞下游；启动组合外依赖需要在关系中明确允许。
- `related`：建立关联，不改变启动顺序。

循环关系会被拒绝。独立分支并行启动，有依赖的分支等待前提满足。一个分支失败时，已经成功的分支保留运行。停止组合会释放它的使用关系，保护仍被其他组合或独立启动使用的服务。强制停止可能影响这些使用方。

启动时选择默认运行时，也可以为子应用分别指定位置。私人运行时只有其所有者能使用，工作区管理员身份不会授权在其他成员的私人机器上执行。

HTTP 服务依赖可以配置 `API_URL` 等连接绑定，并添加相应的依赖关系。目标服务必须提供端口。同一机器使用本地地址；跨运行时连接要求目标已发布，向应用注入私有本地代理地址，连接凭证留在应用管理进程内。停止或替换源、目标实例，取消发布或撤销运行时权限，都会使远程连接失效。

## 启动、发布与访问

启动负责运行服务并检查就绪。发布为运行实例建立受认证的访问入口；开启自动发布后，在就绪时发布。取消发布关闭访问入口，保留服务进程。

自托管部署需要配置 `MULTICA_APPLICATION_ORIGIN`，使用独立的应用通配域名，并配置对应 DNS 和 TLS。应用域名必须与 Multica 管理域名分离。配置和多节点网关路由见[环境变量](/environment-variables)。

从 Multica 打开应用时，单次启动票据兑换为仅用于该应用的会话。平台登录凭证不会传给服务。HTTP、WebSocket、SSE、上传和下载通过运行时主动建立的隧道访问。目前不提供公网匿名分享。

## 状态、日志与恢复

进程、健康、发布和运行时连接分别展示。运行时离线不代表服务已停止。查看操作步骤定位部分失败和依赖阻塞；操作被接受不代表执行完成。

日志支持游标续读、暂停、搜索和下载已加载内容。日志有容量与轮转上限；出现缺口表示较旧内容已不可获取。停止后的日志在本地保留且运行时可达时仍可读取。秘密值应通过本地环境变量引用提供，不能当作普通配置变量保存。应用输出会脱敏已知凭证。

守护进程开启 GC 时，已确认停止的日志和私有仓库目录保留 7 天。清理前核对近期完整运行时列表和本地进程所有权，保护运行中的服务、共享借用者、待交付结果及用户原始项目目录。停止回执继续保留，用于拒绝旧运行版本的指令。失去工作区成员身份后，成功同步工作区列表时会停止这台机器上属于该工作区的服务，不影响其他工作区。

进程自动重试有次数上限，需要主动开启。机器重启后的恢复单独配置，默认关闭。取消未完成操作后显示 `cancelling`，等待停止或恢复确认；独立完成的分支和共享服务不会被一并撤销。

操作期限包含 3 小时排队等待，以及服务配置中的代码准备、健康检查和重试预算。取消后的核对期限为 15 分钟。超时会结束操作并撤销旧执行租约，保留已成功的分支；未确认停止的服务在运行时重连后继续核对，不会因为超时就显示已停止。成员退出后，旧会话、连接凭证和启动票据持续失效；重新加入需要重新授权。

删除应用前，先停止活动实例并移除其他应用指向它的关系。删除项目或运行时时，会列出必须先处理的活动服务和待完成操作。

## CLI 与智能体工具

CLI 与界面采用相同的项目和运行时权限检查：

```bash
multica application list --project "项目名称"
multica application get <application-id>
multica application plan <application-id>
multica application start <application-id> --body-file start.json --wait
multica application status
multica application operations <application-id>
multica application logs <application-id> --instance <instance-id>
multica application cancel <application-id> <operation-id> --wait
```

`start.json` 包含当前 `revision`、目标 `runtime_id` 和唯一的 `idempotency_key`。可选的 `placements` 将子应用 ID 映射到运行时 ID。同一个幂等键用于重试同一操作。CLI 等待超时只结束等待，不会取消操作。

`create` 和 `update` 通过 `--body-file` 提交配置与关系。`stop`、`restart`、`publish` 和 `unpublish` 同样需要版本、运行位置和幂等键。`launch` 与 `service-access` 必须指定 `--endpoint`；返回地址与凭证应按敏感信息处理。

支持应用能力的智能体运行会收到 `multica-applications` MCP 服务，提供应用目录、控制、状态、操作、日志和访问授权工具。工具受当前运行的项目与运行时权限约束。不要把访问凭证写入任务报告。
