## 0. 文档说明

### 0.1 目的与范围

本文档描述 `lsiten/multica` fork 的全部产品功能需求。相对上游，fork 的核心增量是把「本地智能体运行时」从**不可见、不可干预**推进到**可视、可控、可评审、可自托管、可独立分发**。

**在范围内**：运行时镜像、远程控制、虚拟屏、daemon 多进程体系、任务隔离、会话文档化、议题工作进度、本地 MR、Jev 决策模型、应用托管、通信渠道、桌面端、发布与部署。

**不在范围内**：上游既有的通用能力（账号、工作区、计费、基础项目管理等），除非 fork 做了显著改动。

### 0.2 目标读者

产品经理、架构师、前后端与桌面端工程师、测试与运维。文档同时用于交接与合规评审。

### 0.3 术语表

| 术语 | 定义 |
| --- | --- |
| **Runtime（运行时）** | 一台运行 daemon 的机器，是任务执行与屏幕采集的物理载体 |
| **Daemon** | 常驻本机的守护进程，负责任务执行、环境准备、屏幕采集、GUI 控制 |
| **Mirror（镜像）** | 把一个 runtime 的屏幕实时投送到浏览器，点对点，服务端不经手像素 |
| **Vscreen（虚拟屏）** | daemon 通过原生宿主创建的托管显示，智能体在其中操作应用 |
| **Lease（租约）** | 对某个显示资源的限时独占权，过期自动释放 |
| **Grant（授予）** | 观看或控制的短期凭证，30 秒有效，可续期 |
| **MR（本地合并请求）** | 在 runtime 本地仓库上完成的分支评审与合并，不经远端托管平台 |
| **Worktree** | 为单个任务从同一仓库签出的独立工作树 |
| **Jev** | 决策模型子系统，为智能体提供结构化判断与完成度校验 |
| **Squad（小队）** | 一组智能体的协作单元，有 lead 与协作协议 |
| **Inbox（收件箱）** | 站内通知中心，也是外部 IM 推送的来源 |

### 0.4 角色定义

| 角色 | 说明 | 关键权限 |
| --- | --- | --- |
| **Workspace Owner / Admin** | 工作区所有者或管理员 | 配置 Jev、镜像网络、应用发布、管理小队 |
| **Member（成员）** | 普通工作区成员 | 查看公开 runtime、发起会话、参与评审 |
| **Runtime Owner** | runtime 的归属者（`owner_id`） | 开启主机交互开关、紧急停止、一键夺回 |
| **Local User（本机用户）** | 物理坐在 daemon 机器前的人 | 本地夺回窗口、授权系统权限 |
| **Agent（智能体）** | 执行任务的 AI 实体 | 通过 MCP 工具操作虚拟屏、调用决策模型 |
| **Machine Credential** | 机器凭据（CLI / CI） | **不得**执行需要人类的敏感操作（如改 Jev 配置） |

### 0.5 优先级定义

| 级别 | 含义 | 交付要求 |
| --- | --- | --- |
| **P0** | 核心链路，缺失即功能不可用 | 必须实现并有自动化验收 |
| **P1** | 重要体验或安全边界 | 必须实现，验收可人工 |
| **P2** | 增强能力、可观测性、运维便利 | 可排期，允许降级 |

## 2. 运行时镜像（MIR）

### 2.0 范围与平台边界

镜像把 runtime 的屏幕内容从 daemon 所在主机采集，经 WebRTC 直连观看端。**服务端只做信令、授权与仲裁状态，不转发、不存储任何像素。**

| 能力 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 观看（v1 JPEG 分片） | ✅ | ✅（GDI 主显示器） | ❌ 明确提示不支持 |
| 观看（v2 H264） | ✅ | ❌ | ❌ |
| 虚拟屏 / 源选择 | ✅ | ❌ | ❌ |
| 人类远程控制 | ✅ | ⚠️ 有注入实现但不上报能力，产品路径不可达 | ❌ |
| 智能体代操作 | ✅ | ❌ | ❌ |
| 窗口认领 | ✅ | ❌ | ❌ |
| 本地一键夺回 | ✅ | ❌ | ❌ |

**约束**：Linux 必须显式显示「暂不支持」，不得静默失败或伪装成离线。

### 2.1 FR-MIR-01 镜像入口

- **角色**：Runtime Owner、可读该 runtime 的成员
- **优先级**：P0
- **行为**：runtime 列表每行提供「查看屏幕」入口；多台本机 runtime 时以下拉选择。
- **规则**：
  - 可读判定 = `owner_id == 当前用户` 或 `visibility == public`。
  - 不可读：入口不渲染（不是禁用）。
  - 不可用：入口禁用 + tooltip 给出**具体原因**（离线 / daemon 过旧 / Linux 不支持 / 平台不支持）。
- **验收**：
  1. private runtime 对非 owner 不显示入口。
  2. Linux runtime 显示「不支持」而非「离线」。
  3. 缺 `screen-mirror-v1` 的 macOS/Windows daemon 显示「请升级 daemon」。
  4. 点击进入 `/runtimes/{id}/mirror`，runtime 不存在时展示不可用页面态。

### 2.2 FR-MIR-02 镜像页面结构

- **优先级**：P1
- **行为**：页面由标题、Pin 按钮、固定比例镜像子表面（16:9）、源选择器、重试、浮窗、全屏、清屏组成；底部状态行显示状态文案、协商的 `宽 × 高 · FPS`，并在浏览器提供实测值时追加接收 FPS、码率、RTT 与丢包率。
- **规则**：
  - 镜像是**固定子表面**，不做自由布局；不得让视频挤压成任意比例。
  - 帧只在**完整新帧**到达时替换，避免撕裂；半帧不渲染。
  - Pin 类型为 `runtime_mirror`，跨刷新保持。
  - 全屏切换不重建 WebRTC 会话。
  - 清屏只隐藏浮层，视频继续播放。
- **验收**：
  1. 刷新后 Pin 状态保持。
  2. 全屏进入/退出后会话 ID 不变。
  3. 清屏后浮层消失但帧率不降为 0。
  4. 首次统计尚未形成区间时仍显示协商 FPS；统计请求失败或会话关闭后不保留旧的码率、RTT 或丢包率。

### 2.3 FR-MIR-03 会话建立

- **优先级**：P0
- **主流程**：
  1. 取 ICE 配置（`GET /mirror/config`）。
  2. 建立 `RTCPeerConnection` 与数据通道（`mirror`、`mirror-control`，v2 另有 `mirror-input`）。
  3. 生成 offer；v2 补充 `max-recv-level` 能力协商。
  4. `POST /runtimes/{id}/mirror/sessions` 携带 offer 与源绑定。
  5. 服务端校验权限、能力、源绑定 → 创建会话 → 经 WS 下发 daemon。
  6. daemon 回 answer → 浏览器轮询获取 → `setRemoteDescription`。
  7. 首帧到达 → 状态 `streaming`。
- **规则**：
  - 会话 TTL 默认 30 秒，上限 5 分钟；SDP ≤ 256 KiB；会话 ID ≥ 32 字节。
  - 状态机：`offered → answered → closed | expired`，失败为 `failed`。
  - offer 与 answer **各只能消费一次**，重放返回冲突。
  - 会话身份为五元组 `{WorkspaceID, RuntimeID, UserID, DaemonID, ViewerID}`，任一不符即拒绝。
  - 无权限统一返回 404（不泄露 runtime 是否存在）。
- **异常**：
  | 场景 | 返回 | 前端表现 |
  | --- | --- | --- |
  | daemon 离线 | 409 `offline` | 「运行时离线」 |
  | 缺能力 | 501 `upgrade_required` | 「请升级 daemon」 |
  | 无权限 | 404 | 「无权访问」 |
  | 未 answer 超时 | 会话 `expired` | 「连接超时」+ 重试 |
- **验收**：
  1. 同一 offer 提交两次，第二次冲突且不产生第二条会话。
  2. 超 30 秒未 answer 的会话查询返回 `expired`。
  3. 非成员访问所有镜像端点均 404。

### 2.4 FR-MIR-04 观看路径 v1（JPEG）

- **优先级**：P0
- **规则**：
  - 帧头 11 字节、块头 7 字节，单块 payload ≤ 12 KiB；JPEG 质量 60。
  - 首个观看者触发采集，最后一个离开即停止采集（节省 CPU）。
  - 仅主显示器；macOS 需要「屏幕录制」权限。
  - 采集失败广播 `mirror:error` 并移除观看者。
- **验收**：
  1. 首帧前为 `negotiating`，首帧后 `streaming`。
  2. 最后一人离开后 daemon 停止采集（CPU 回落）。
  3. 帧序号缺失时不渲染半帧。

### 2.5 FR-MIR-05 观看路径 v2（H264）

- **优先级**：P1
- **规则**：
  - 需同时满足：`protocol_version=2`、`transport="video"`、有效源绑定、有效观看凭证，缺一即拒。
  - 质量协商：接收 level < 4.0 → 1280×720 / 14 Mbps；≥ 4.0 → 1600×900 / 20 Mbps；上限 30 FPS；宽高必须偶数。
  - 同一源共享一个编码器；订阅队列容量 3；新订阅者必须等关键帧。
  - 收到 RTCP PLI/FIR 时强制关键帧。
- **验收**：
  1. 浏览器不支持 H264 时自动回退 v1 页面。
  2. 两个观看者只启动一个编码器。
  3. 元数据与实际源代际不符时判 `source_gone`，不显示错位画面。

### 2.6 FR-MIR-06 观看凭证与续期

- **优先级**：P0
- **规则**：
  - 观看凭证 TTL 30 秒；前端每 10 秒续期。
  - 续期必须重新校验：daemon 在线、源代际与目录一致、用户仍有权限。
  - 续期只能延长过期时间，**不能延长身份**。
  - 撤销只影响指定凭证；daemon 换代时该 daemon 全部凭证失效。
  - 服务端每 10 秒清扫过期凭证，容量上限 4096。
- **验收**：
  1. 30 秒不续期自动失效，画面停止。
  2. 源代际变化后返回 `stale_generation`，不静默续期。
  3. 续期推送失败时立即撤销，不留悬挂凭证。

### 2.7 FR-MIR-07 断线重连

- **优先级**：P1
- **规则**：
  - 仅对可自愈原因自动重连：传输失败、协商超时、协商失败、会话过期。
  - 退避 1s → 2s → 4s → 8s → 16s，最多 5 次。
  - `disconnected` 有 5 秒宽限，超时判传输失败。
  - 页面隐藏（`pagehide`）主动关闭会话。
- **验收**：
  1. 断网 5 秒内显示「传输失败」。
  2. 恢复后手动重试可继续。
  3. 关闭页面后 30 秒内 daemon 侧 peer 被回收。

### 2.8 FR-MIR-08 源选择

- **优先级**：P1（仅 macOS）
- **行为**：下拉列出虚拟屏 / 物理屏 / 系统屏，标注类型；默认自动选中 `ready` 状态的虚拟屏。
- **规则**：
  - 源身份 = `(kind, sourceId, nativeEpoch, generation)` 四元组，任一变化即为不同源。
  - 映射：拥有的显示 → 虚拟屏；内置显示 → 物理屏；其他 → 系统屏；外部窗口不暴露。
  - 切换源**必须**使旧控制授予失效。
- **验收**：
  1. 首次加载若存在 ready 虚拟屏，自动选中。
  2. 代际变化后旧选择标记不可用并阻止输入。
  3. 目录中不出现其他工作区/其他 runtime 的窗口。

### 2.9 FR-MIR-09 观看通知

- **优先级**：P2
- **规则**：
  - 仅在**首个**观看者进入与**最后**一个离开时通知 owner。
  - 受工作区设置 `viewer_notifications_enabled` 控制，默认开；关闭后不产生通知但审计仍记录。
  - 通知失败不影响会话。
- **验收**：
  1. 两人先后进入只产生 1 条 started。
  2. 最后一人离开才产生 stopped。
  3. 关闭设置后无通知。

### 2.10 FR-MIR-10 审计事件

- **优先级**：P2
- **规则**：
  - 记录 `session_started / session_answered / session_failed / viewer_started / viewer_stopped`。
  - 查询上限 500 条，默认 100；支持清空。
  - best-effort 写入，失败只告警，不阻断会话。
- **验收**：会话失败可在审计中按 `failure_reason` 检索。

### 2.11 FR-MIR-11 镜像网络配置（TURN）

- **优先级**：P1
- **行为**：管理员在 Workspace 设置中查看网络来源、TURN 状态、Cloudflare 状态、观看通知开关。
- **规则**：
  - 优先级：环境变量 → 自定义 → 关闭 → 内置 → 内置不可用。
  - 部署环境变量存在时配置**锁定**，界面不可改。
  - 内置 TURN **默认关闭**（opt-in）。
  - Cloudflare 凭据 TTL 夹在 5 分钟–48 小时（默认 24 小时），提前 10 分钟刷新；过滤 `:53` 候选。
  - 新凭据保存时立即校验，不允许延迟到运行时会话才失败。
- **验收**：
  1. env 锁定时修改返回 409。
  2. 错误 Cloudflare 凭据在保存时即报错。
  3. 关闭模式不返回任何 TURN 服务器。
  4. `:53` 候选不下发到浏览器。

## 3. 远程控制（CTL）

> **隐私红线**：服务端不记录、不转发、不存储任何输入事件、文本内容、坐标流。输入经 WebRTC DataChannel 直连 daemon。

### 3.1 FR-CTL-01 主机交互主开关

- **角色**：Runtime Owner
- **优先级**：P0
- **行为**：镜像页提供「启用交互 / 关闭交互」；开启前触发系统辅助功能授权。
- **规则**：
  - **默认关闭**；只约束人类，不约束智能体。
  - 关闭立即撤销该 runtime 全部控制授予。
  - 非 owner 调用返回 403。
  - 命令幂等，回执缓存 1 小时、上限 1024 条。
- **验收**：
  1. 默认状态下申请控制返回 `interaction_disabled`。
  2. 开启后 5 秒内控制条可操作。
  3. 关闭后所有观看者立即失去控制，已按下的鼠标被释放。
  4. 非 owner 无法开启/关闭/紧急停止。

### 3.2 FR-CTL-02 控制授予（Control Grant）

- **优先级**：P0
- **九道检查（顺序敏感）**：
  1. daemon 在线，否则 409 `offline`。
  2. 具备 `screen-control-v1`，否则 501 `upgrade_required`。
  3. 请求体 ≤ 4096 字节。
  4. 虚拟屏不得直接申请，返回 400 `virtual_interaction_requires_takeover`。
  5. 主机开关必须开启，否则 409 `interaction_disabled`。
  6. 源必须与实时目录精确匹配代际；缺失 `source_unavailable`，代际不符 `stale_generation`。
  7. 必须存在活跃的观看凭证且源一致，否则 `viewer_grant_required`。
  8. 同一用户同源复用 `GrantID`；不同用户返回 403；续期但无授予返回 409。
  9. 写入并下发失败则回滚或撤销。
- **规则**：
  - TTL 30 秒，前端每 10 秒续期；续期失败回到只读。
  - 容量 4096，键为 `runtimeID + viewerID`。
  - 撤销触发点：观看者离开、daemon 断连、关闭开关、紧急停止、过期清扫、主动删除。
- **验收**：
  1. 无活跃观看凭证时无法获得控制授予。
  2. 续期不改变 `GrantID`。
  3. 切换源后续期失败并回到只读。
  4. 观看者关闭页面后 10 秒内授予被撤销。

### 3.3 FR-CTL-03 输入事件与五道闸门

- **优先级**：P0
- **支持的事件**：

| 事件 | 参数 | 手势语义 |
| --- | --- | --- |
| `pointer:down` / `up` / `move` | button ∈ left/middle/right | down 起持锁，up 释放 |
| `wheel` | Δx / Δy | 原子手势，立即释放 |
| `key:down` / `up` | 键 + 修饰键 | down 起持锁，up 释放 |
| `type` | 整段文本（≤ 1024 rune） | 原子手势 |

- **消息上限**：单条 ≤ 16 KiB。
- **五道闸门（必须按序）**：
  1. 授予有效性与序列号递增（防重放）。`seq` 在仲裁前消费。
  2. 主机开关仍开。
  3. 资源解析与代际匹配。
  4. FCFS 仲裁：抢不到返回 `busy`。
  5. 派发前最终复核并注入。
- **回执**：`mirror-input:ack` / `:nack`，原因 ∈ `busy | stale | denied | unsupported`。
- **前端处理**：`busy` 不报错只记录；`stale` / `denied` 回到只读。
- **验收**：
  1. 无授予时发送输入一律 `denied`。
  2. 几何变化后旧坐标返回 `stale`，不会点错位置。
  3. 按住鼠标未松开超 5 秒自动释放。
  4. 同一手势 ID 重复发送只算一次。

### 3.4 FR-CTL-04 坐标映射

- **优先级**：P0
- **规则**：
  - 浏览器按 `object-fit: contain` 计算，含黑边偏移并夹取到帧内。
  - daemon 侧：`帧像素 → 逻辑点 + 显示器原点`。
  - Windows 再归一化到 0..65535（若支持）。
- **验收**：
  1. Retina（编码 2x / 逻辑 1x）下点击与系统光标一致。
  2. 双屏（含负坐标）时落在正确显示器。
  3. 黑边区域点击被夹取，不越界注入。

### 3.5 FR-CTL-05 键盘与文本注入

- **优先级**：P1
- **键白名单**：A–Z、0–9、enter/return/tab/space/escape/backspace/delete/方向键；修饰键 shift/control/alt/meta。
- **规则**：
  - macOS 用 `CGEventPost` 到 HID tap，需辅助功能权限；文本逐字符注入以绕过键盘布局。
  - Windows 用 `SendInput`；修饰键在 key:up 时**逆序释放**，避免卡住 Ctrl/Shift；文本用 Unicode 事件，正确处理 emoji 与生僻字。
  - 输入法组字期间按 Enter 不发送。
  - 含 meta/ctrl/alt 的组合键在视频区不上送，避免与浏览器快捷键冲突。
- **验收**：
  1. 中文与 emoji 可完整输入。
  2. Ctrl+C / Ctrl+V 通过控制条按钮生效。
  3. 长按修饰键后松开不残留。

### 3.6 FR-CTL-06 多观看者协调（FCFS）

- **优先级**：P1
- **规则**：
  - 按「显示资源」串行化**原子手势**；不同资源互不阻塞（人在物理屏不阻塞智能体在虚拟屏）。
  - **不排队**：抢不到立即 `busy`，由前端自行重试。
  - 只有手势期间持锁，不做会话级独占。
  - 过期锁惰性清理；主体掉线后 5 秒内自动释放。
  - Owner 不抢占他人，只能紧急停止。
- **验收**：
  1. A 拖拽期间 B 点击得 `busy`，A 松开后 B 重试成功。
  2. A 掉线后锁 5 秒内释放。
  3. 不会出现两条交错拖拽轨迹。

### 3.7 FR-CTL-07 控制态广播

- **优先级**：P2
- **规则**：daemon 状态变化 → 服务端 → WS 广播 `runtime_mirror:control`；`0↔1` 变化时写收件箱（开始为 attention，结束为 info）。
- **验收**：
  1. 同一 runtime 同时最多一个 active controller 展示。
  2. 控制者离开后 10 秒内他人可申请。
  3. 断连后状态被重置。

### 3.8 FR-CTL-08 镜像页语音输入

- **优先级**：P2
- **规则**：
  - 单段 ≤ 60 秒 / 512 KiB；转写超时 25 秒；每连接 2 并发；全局 32 并发。
  - 需 daemon 配置转写器；未配置时按钮不可用，不误导用户。
  - 语音通道断开不影响视频与控制。
- **验收**：
  1. 松开后 ≤ 25 秒返回文本或明确超时。
  2. 超过 60 秒自动截断。
  3. 未配置转写器时按钮不可点。

### 3.9 FR-CTL-09 紧急停止

- **角色**：Runtime Owner、本机用户
- **优先级**：P0
- **行为**：一键立即中止所有远程输入。
- **规则（必须全部执行）**：
  1. 关闭主机交互开关。
  2. 清空该 runtime 全部远程手势锁。
  3. 撤销该镜像全部控制授予。
  4. 前端停止控制并刷新状态。
  - 语义：**本地永远可以中止远程**，不受 FCFS 顺序限制。
  - 智能体租约不受影响（若仍有效则继续）。
- **验收**：
  1. 执行后 1 秒内远程输入全部 `denied`。
  2. 正在拖拽的手势立即释放，不残留按下状态。
  3. 所有观看者控制按钮变为不可用。

### 3.10 FR-CTL-10 虚拟屏的交互例外

- **优先级**：P1
- **规则**：人类不能像操作物理屏那样自由点击虚拟屏；必须通过「干预接管」获得窗口级授权。
- **理由**：虚拟屏由智能体租约持有，自由注入会破坏租约的原子性。
- **验收**：对虚拟屏申请控制授予返回 `virtual_interaction_requires_takeover`。

## 4. 虚拟屏与 GUI 自动化（VSC）

### 4.0 领域模型

| 概念 | 构成 | 说明 |
| --- | --- | --- |
| `ResourceKey` | BackendIdentity, WorkspaceID, RuntimeID, UID, DisplayID | 显示资源的唯一标识 |
| `VscreenEpoch` | NativeEpoch, DisplayGeneration, GeometryRevision | 任一项变化使旧输入/动作失效 |
| `Lease` | Resource, TaskID, TransactionID, LeaseEpoch, NativeEpoch, ExpiresAt, Cancelled | 任务对资源的限时独占 |
| `AppClaimKey` | UID, PID, ProcessStartIdentity | 进程级身份，防止冒领 |
| `MirrorSource` | kind(virtual/physical/system), SourceID | 可投送的屏幕 |

### 4.1 FR-VSC-01 原生显示宿主

- **优先级**：P0（macOS）
- **协议规则**：
  - 通过继承的文件描述符通信；token 常量时间比较。
  - 单条消息 ≤ 64 KiB，4 字节长度前缀；拒绝未知字段。
  - 操作集：`hello / list / sources / start_capture / stop_capture / force_keyframe / capture_status / ensure / describe / quiesce / dispose`。
  - `ensure` 尺寸边界 320..4096 × 240..2160；资源上限 16；需运行时认领。
  - 几何变化 → `GeometryRevision++` 且必须重新静默（quiesce）才能继续动作。
  - `dispose` 必须先 quiesce。
- **验收**：
  1. 超边界请求被拒且不创建显示。
  2. 第 17 个资源被拒。
  3. 几何变化后未 quiesce 的动作被拒。
  4. 宿主崩溃后 daemon 标记 `unavailable`。

### 4.2 FR-VSC-02 租约与所有权

- **优先级**：P0
- **规则**：
  - 每个资源一个 Actor，FIFO 排队；取消只移除自身 waiter。
  - 心跳 4 秒续期；租约 TTL 15 秒；事务上限 120 秒；单动作超时 3 秒。
  - 释放必须先静默再交接；每 5 秒清扫。
  - 冻结时取消租约并把排队者唤醒为 `action_uncertain`。
- **验收**：
  1. 两个任务竞争严格 FIFO。
  2. 取消排队不影响其他顺序。
  3. 租约过期后可被下一任务获得。
  4. 交接前完成静默，不出现双写。

### 4.3 FR-VSC-03 窗口认领

- **优先级**：P1（macOS）
- **行为**：本机用户选择要交给智能体的应用窗口，运行时认领后在虚拟屏中复用。
- **规则**：
  - 锁目录权限 0700；锁文件名为身份的 SHA-256；`flock` 非阻塞；禁止跟随符号链接；校验属主、普通文件、权限位 0。
  - 身份含进程启动标识，PID 复用不能复用旧锁。
  - 认领的 UID 必须与资源 UID 一致。
  - 释放必须在静默之后。
- **验收**：
  1. PID 重启后旧锁不能复用。
  2. 伪造 UID 的认领被拒。
  3. 并发认领同一窗口只有一个成功。

### 4.4 FR-VSC-04 PID 输入策略

- **优先级**：P1
- **规则**：
  - 按 BundleID / 版本 / 构建号 / 签名 ID / 代码哈希 / 系统构建匹配。
  - 允许的输入变体：坐标主键点击、像素滚动、主键拖拽、Unicode 文本、指定按键组合。
  - 键盘策略要求输入源一致。
  - 校验结论（未校验 / 已验证变体）必须出现在观察结果中，供上层决策。
- **验收**：
  1. 不在白名单的应用返回 `needs_intervention`。
  2. 代码哈希长度非法直接拒绝。
  3. 键盘变体与输入源不一致时拒绝。

### 4.5 FR-VSC-05 智能体 GUI 工具集

- **优先级**：P0（macOS）
- **工具**：`vscreen_status / acquire / release / list_apps / launch_app / observe / click / drag / scroll / type / key / ui_tars`。
- **规则**：
  - `observe` 返回截图（PNG）+ 可访问性元素 + 快照版本号。
  - `click` = down + up；`drag` 时长 1..3000 ms；`scroll` 固定步长。
  - 动作幂等：动作 ID + 序号严格递增；快照版本必须匹配；代际变化返回 `action_uncertain` 并冻结。
  - 抢不到资源返回 `VscreenAppInUse`，单 FIFO waiter。
  - 任务停止后不再执行任何排队动作。
- **验收**：
  1. 重复提交同一动作不产生二次点击。
  2. 几何变化后旧坐标动作被拒。
  3. 租约 15 秒不续期自动释放。

### 4.6 FR-VSC-06 视觉决策（UI-TARS）

- **优先级**：P2
- **规则**：
  - 端点仅允许 https 或 loopback http；禁止重定向。
  - 目标描述 ≤ 16384 字符；图片必须是 PNG 且 ≤ 8 MiB；超时 45 秒。
  - 动作语法：`wait()`、`finished()`、`click(start_box)`、`type(content)`、`hotkey(keys)`、`scroll(point, direction)`；越界报错。
  - 解析失败不得执行部分动作。
- **验收**：
  1. 非 https 且非 loopback 的端点被拒。
  2. 超过 8 MiB 或非 PNG 被拒。

### 4.7 FR-VSC-07 干预与一键夺回

- **优先级**：P1（macOS）
- **状态机**：

```
awaiting_takeover ──本地夺回──▶ human ──归还+新截图──▶ ready_to_continue ──续跑──▶ continued
        │                          │
        └──────── 取消 ────────────┴──▶ cancelled
   进程重启/代际变化 ──▶ stale
```

- **规则**：
  - 只有 runtime owner 可发起夺回、归还、续跑、取消。
  - 本地夺回要求：owner 能力已验证 + 干预报告已被服务端确认。
  - 归还前必须为每个窗口取得**新的原生观察**，才生成归还回执。
  - 续跑必须校验干预/任务/回执/代际/agent/工作区全部相等，并消费回执。
  - 进程重启后从磁盘加载的记录一律置 `stale`，不恢复任何权威。
- **验收**：
  1. 报告未确认时夺回被拒，提示「报告待确认」。
  2. 归还后没有新截图不能进入可续跑。
  3. 旧代际续跑被拒。
  4. 重启后旧干预显示 stale。

### 4.8 FR-VSC-08 镜像页指挥智能体

- **优先级**：P1（macOS）
- **行为**：镜像页底部选择 agent → 聊天浮层 → 输入需求 → 智能体在**当前选中屏幕**上操作。
- **规则**：
  - 消息携带源上下文（类型 `mirror_source_v1`），服务端与 daemon 均按实时目录复核。
  - 虚拟屏要求已启用且代际匹配；物理屏要求 provider 支持远程 MCP。
  - 会话优先复用该 agent 最近未归档会话，否则新建。
  - 浮层仅在「已选 agent + 有会话 + 未清屏」时渲染。
- **验收**：
  1. 未选源时无法发送代操作消息。
  2. 切换源后旧会话仍可见但新消息绑定新源。
  3. 源过期时任务创建失败并提示。

## 5. Daemon 与运行时体系（DMN）

### 5.1 FR-DMN-01 进程角色与能力门控

- **优先级**：P0
- **角色白名单**：`ai`、`mirror`、`application`、`environment`、`gateway`。
- **默认值**：未配置时五个角色全部启用。
- **规则**：
  - 未知或重复角色 → 配置校验失败，daemon 不启动（fail-closed）。
  - 生产 profile 必须同时声明五个角色；对应能力只允许由子进程持有，不能用进程内 owner 补位。
  - `environment` 生效后，git 与 worktree 操作迁移到子进程。
- **验收**：
  1. 不配置时 `/health.process_services` 返回恰好 5 个角色。
  2. 配置 `["bogus"]` 时 daemon 启动失败且不监听端口。
  3. 只声明 `["ai"]` 或显式空列表时配置校验失败，daemon 不启动。

### 5.2 FR-DMN-02 强制子进程 owner 与 fail-closed

- **优先级**：P0
- **规则**：
  - 子进程启动失败或执行授权失败时，daemon fail-closed 退出，不回落到进程内 provider、MCP、应用或环境 owner。
  - 任务 worker 拒绝、旧服务端缺少 execution reconciliation 或 transport outcome 不确定时，任务进入明确错误/待重试状态，控制进程不得再次执行 provider。
  - 状态可见：`starting`（进程激活但尚未就绪）/ `ready`（有 pid）/ `failed`（缺少必需 owner）。
- **验收**：
  1. 人为让 environment 子进程失败：daemon 不进入 `running`，并返回带 owner 名称的启动错误。
  2. 旧服务端不提供 execution reconciliation：worker 任务 fail-closed，不执行进程内 provider。
  3. daemon 退出时已启动的子进程被关闭，无孤儿。

### 5.3 FR-DMN-03 子进程控制通道

- **优先级**：P0
- **规则**：
  - 私有 HTTP-over-loopback，协议版本 1；bootstrap 只经 stdin 传递，不出现在 argv/env。
  - 仅接受 `POST /rpc`；Bearer token 常量时间比较；只接受 `127.0.0.1` 来源。
  - 作用域：`{Backend, Account, Profile, DaemonID, Service}`；实例身份在生命周期内不可变。
  - 上限：请求体 256 KB、日志 8 MB、操作 128 条；期限必须 > now 且 ≤ 5 分钟。
  - 错误码族：`unauthorized / identity_mismatch / malformed / payload_too_large / deadline / request_conflict / retired_request / stale_fence / draining / stopped / resource_exhausted / unknown_operation`。
- **验收**：
  1. 伪造 Bearer 返回 401 且不产生回执。
  2. 同一请求 ID 不同内容返回 409。
  3. 期限设为过去或 10 分钟均返回 408。
  4. 300 KB 请求体返回 413，进程不退出。

### 5.4 FR-DMN-04 记录持久化与崩溃恢复

- **优先级**：P0
- **规则**：
  - 每个「作用域 + 实例」一个私有目录，`owner.json` 原子写（临时文件 → fsync → 替换 → 目录同步）。
  - 拒绝符号链接祖先；目录 0700；校验普通文件与权限位。
  - 崩溃后发现旧记录 → 在域锁内证明旧清单安全 → 归档为 `reconciled-<instanceID>.json` → 新记录状态 `ready` 且操作清空。
  - 归档上限 64 个 / 64 MiB；**绝不自动重放**。
  - 发现记录时必须重算哈希、校验身份与来源，防止目录污染。
- **验收**：
  1. kill -9 后重启，旧记录被归档，新记录无未决操作。
  2. 归档已存在且内容不同时拒绝，不改写 owner。
  3. 域内仍有未停止进程时不退休（不误杀）。
  4. 第 65 个归档触发配额错误。

### 5.5 FR-DMN-05 回执、准入与确认

- **优先级**：P0
- **规则**：
  - 所有变更先写 pending 回执再执行，结果落 completed；只有显式确认才退休记录。
  - 同请求 ID 同内容重放返回上次结果，**副作用只发生一次**。
  - 准入顺序：期限 → 指纹 → 冲突 → 前缀/纪元 → 围栏 → 状态 → 配额。
  - 并发：生命周期独占；普通变更最多 4 并发；避免 `stop → ordinary → confirmation` 死锁。
  - 取消后 2 秒内无法证实的操作**保持 pending**，不写完成、不重放；写盘失败则标记 `suspect`。
- **验收**：
  1. 未确认前重复提交同请求，副作用次数 = 1。
  2. pending 未解决时批量确认返回 409 `uncertain_operation`。
  3. 同时 5 个变更，峰值并发 ≤ 4。
  4. drain 期间新普通变更返回 409 `draining`。

### 5.6 FR-DMN-06 Worker 进程（每任务一次性）

- **优先级**：P1（生产强制开启）
- **开关**：无独立开关；每个已 claim 的 task 都必须由一次性 worker 子进程承载。
- **规则**：
  - 每个执行一个 worker，承载 provider 启动与工具调用；**不共享凭据**。
  - 无运行上下文则 fail-closed，不跑 provider。
  - 缺少可执行文件时直接报错，**不做进程内兜底**（与常驻服务不同）。
  - 崩溃后结果通过 `review-artifacts/.pending-*` 兜底落地，下次启动捞回并上报一次。
  - 状态接口不含凭据。
- **验收**：
  1. 缺少 worker 可执行文件或 execution reconciliation 时任务 fail-closed，不在 daemon 内执行 provider。
  2. 正常执行时进程列表出现该执行且状态 `ready`。
  3. 停掉 worker 后任务被标记失败而非挂起。
  4. 大结果写出前被 kill，重启后只上报一次。

### 5.7 FR-DMN-07 模型服务（modelservice）

- **优先级**：P1
- **规则**：
  - 租约 90 秒、上限 128；单租约并发 4；上游必须是 loopback http，禁止重定向。
  - 请求体 ≤ 1 MiB，响应 ≤ 2 MiB，超时 3 分钟。
  - 上游非 loopback 一律拒绝（防 SSRF）。
  - 进程重启时若「可能存在后代进程」则拒绝启动，避免双推理进程。
  - 环境变量白名单化（PATH/HOME/代理/CUDA 等）。
- **验收**：
  1. 第 129 个租约返回 busy。
  2. 90 秒不续期返回 `lease_lost`。
  3. 上游指向公网域名被拒。

### 5.8 FR-DMN-08 与 Server 的连接、心跳与抢占

- **优先级**：P0
- **规则**：
  - WS 承载唤醒与 RPC v1；心跳 60 秒超时、54 秒 ping。
  - 单客户端最多 8 个在途 RPC，超出返回 429。
  - WS 抢占结果不确定时**本轮跳过**，不回退 HTTP（避免双 claim）。
  - 服务端不支持 RPC v1 时全程走 HTTP 抢占。
  - 连接换代后旧代际标记失效。
- **验收**：
  1. 断网后 ≤ 30 秒重连，断开期间不产生重复 claim。
  2. 超时（uncertain）后本轮不发起 HTTP claim。
  3. 第 9 个并发 RPC 返回 429。

### 5.9 FR-DMN-09 任务结果 409 围栏

- **优先级**：P0
- **规则**：以下任一不符即返回 409 `task execution is stale or unauthorized`：
  - 已撤销；执行 ID / worker ID / runtime ID / 下发时间不符。
  - 执行成员关系缺失；授权不含该操作；授权过期。
  - 有执行行但无授权哈希（禁止降级为无身份写）。
  - 完成时间超过 24 小时且非恢复路径。
- **验收**：
  1. 用旧执行 ID 完成返回 409，任务状态不变。
  2. 正确身份且未过期返回 200。
  3. 规范化重放返回 200 而非 409。

### 5.10 FR-DMN-10 终态上报队列与隔离区

- **优先级**：P1
- **规则**：
  - 文件即队列，每任务一文件，目录 0700、文件 0600；不含 auth token。
  - 退避 5 秒 → 5 分钟；4 个重放 worker。
  - 永久拒绝判定：400/403、404（仅任务不存在）、409（仅终态冲突）。
  - 累计 3 次**且**跨度 ≥ 10 分钟才移入隔离区；complete 被隔离后补发一条 fail 补偿。
- **验收**：
  1. 服务端 500 时按退避重试。
  2. 409 三次且跨度 10 分钟后隔离并产生 fail 补偿。
  3. 401 不触发隔离。
  4. 重启后未发送记录只成功投递一次。

### 5.11 FR-DMN-11 进程总览与本地诊断端点

- **优先级**：P1
- **行为**：桌面端与 CLI 可查看六类进程：daemon、task_worker、application、gateway、environment、mirror。
- **规则**：
  - 未启动的常驻服务**也出现在列表**（`stopped` / `starting` / `failed` / `ready`），生产状态不显示 `running-in-process`。
  - 资源采样 best-effort：单进程与整棵子树分别统计；总量是**去重后的整树足迹**，不等于各行之和。
  - 探针失败显示 `unavailable`，**不隐藏行**。
  - 本地端点要求 Bearer + profile 头一致 + 无 Origin。
- **验收**：
  1. 缺少 application 角色时仍有该行，`detail=required-owner-missing`。
  2. 高并发下总量**小于**各行子树之和（证明去重）。
  3. 带 Origin 头访问 `/worktrees` 被拒。

## 6. 任务隔离与 Worktree（ENV）

### 6.1 FR-ENV-01 目录布局

- **优先级**：P0
- **结构**：
  ```
  <WorkspacesRoot>/<workspace>-<idkey>/<issue|task>-<idkey>/
      worktree/        # git 工作树
      workdir/         # 任务工作目录
      multica-config/  # 任务级配置
      logs/            # 日志
  ```
- **规则**：路径片段上限 24 字符；目录含 `.gc_meta.json`（回收元数据）、`.managed_env.json`（来源证明）、`.task_owner`、`.task_lock`。
- **验收**：两个并发任务的根目录不同且互不可见。

### 6.2 FR-ENV-02 环境变量屏蔽

- **优先级**：P0
- **规则**：以下变量被强制覆盖或忽略：`HOME / PATH / USER / SHELL / TERM / TMPDIR / TMP / TEMP / CODEX_HOME / 各 provider 状态目录 / OPENCLAW_*`。
- **验收**：任务自定义 `HOME=/tmp/x` 被忽略，实际指向任务根内路径。

### 6.3 FR-ENV-03 MCP 配置合并

- **优先级**：P1
- **规则**：
  - runtime 为基底，agent 同名覆盖；agent 配置为空时保留 provider 原生继承。
  - 落地路径按 provider 区分。
  - 准备失败必须回滚，不得改动用户既有 MCP 文件。
- **验收**：
  1. agent 与 runtime 有同名 server 时 agent 胜出，其余 runtime server 保留。
  2. 预先存在的用户 MCP 文件在失败后字节不变。

### 6.4 FR-ENV-04 准备 helper 子进程

- **优先级**：P1
- **规则**：
  - 复杂准备动作在可杀死的 helper 中执行；unix 使用独立进程组，取消时杀整组。
  - helper 使用更窄的环境白名单。
  - 错误类型跨进程传递。
  - 取消后 2 秒内必须终止，不留 in-process goroutine。
- **验收**：准备阶段无限阻塞时，取消任务 2 秒内整组被杀。

### 6.5 FR-ENV-05 worktree 创建与复用

- **优先级**：P0
- **创建链**：解析 git 根 → 锁定仓库（跨进程）→ 清理 stale → 校验 HEAD → 检查未跟踪文件可重放 → 快照用户状态（**失败即中止**）→ 解析任务分支 → 添加工作树 → 修剪已合并分支 → 重放用户状态 → 基线提交 → 记录状态。
- **复用闸门**：
  - 存在**活跃评审**时拒绝复用。
  - 分支归属必须通过 owner 校验。
- **常量**：git 超时 2 分钟；未跟踪文件 ≤ 2000 个 / 200 MiB。
- **验收**：
  1. 同一任务重跑复用同一分支，不同任务互不覆盖。
  2. 有活跃评审时复用返回 busy。

### 6.6 FR-ENV-06 worktree 清理判定链

- **优先级**：P0
- **判定顺序（命中即停）**：`active → unowned → unavailable → review → scope_changed → retained → output → dirty → unpushed`。
- **规则**：
  - 只有用户显式「丢弃改动」且**非自动**清理，才允许对 dirty/unpushed 强删。
  - 自动清理需开启 GC 且未设置「任务后保留环境」。
  - 收尾时先提交残余改动再删工作树；提交失败**故意保留**。
- **验收**：
  1. 有未提交改动时自动清理不删，原因 `dirty`。
  2. 有未推送提交时不删，原因 `unpushed`。
  3. 产出 `output/` 文件时不删。
  4. 手动强删返回已移除路径清单。

### 6.7 FR-ENV-07 评审与清理隔离

- **优先级**：P0
- **规则**：
  - 打开评审**绝不**触发清理（组件测试硬断言）。
  - 只有评审已合并且目标包含该合并，才把下一步动作置为 `cleanup`；且要求无保护原因、任务已结束。
- **验收**：
  1. 点 Review 后清理调用次数为 0。
  2. `approved` 的 worktree 不可清理。
  3. `active` 的 worktree 即使已合并也不可清理。

## 7. 会话与文档（CHAT）

### 7.1 FR-CHAT-01 会话形态

- **优先级**：P0
- **规则**：会话分 `direct`（单 agent）与 `group`（多 agent）；会话含项目/小队归属、置顶、未读、频道来源。
- **验收**：同一会话可切换 agent 而不丢失上下文。

### 7.2 FR-CHAT-02 文档模式

优先级为 P1。`ChatPage` 已挂载 `DocModeSurface`，文件面板的任务预览按钮、附件和运行目录文件可打开对应文档。

- 文档按会话保留选择。文件面板与正文/输入区分列，桌面宽布局默认展开，紧凑布局默认收起，可通过"文件"按钮切换。
- 文档打开时替换消息正文区域，同一会话的输入、离线与权限提示、排队任务继续挂载。运行状态显示在文档区域。
- 工作区成员可编辑已加载的任务正文。运行目录文件通过本地评审适配器合并保存，项目资源目录与附件保持只读。
- 工作区文件预览上限为 64 KiB，截断时显示完整大小。
- 开始编辑时冻结正文和保存基准。查询刷新保留正在编辑的草稿，409 后禁用重复保存，用户放弃后可重新开始编辑。

验收应覆盖从文件面板打开文档、跨会话恢复选择、整篇与选区引用到原会话、发送后保留文档，以及离线、排队、权限受限和紧凑窗口状态。正文区域打开文档时应隐藏消息列表，输入与提示仍可操作。

### 7.3 FR-CHAT-03 内容版本化

优先级为 P1。任务与附件保存线性历史，差异视图可选择历史版本并显示相对当前正文的新增和删除。

- 历史 `revision` 与任务的修改计数分别维护。当前任务文档响应的 `owner_revision` 与正文取自同一任务快照，客户端将该值冻结为 `expected_revision`。兼容旧响应时使用已有 `revision` 字段。
- 服务端在更新任务正文的同一事务中检查修改计数，冲突返回 409。
- 显式 `merge: true` 时，同一作者连续编辑可折叠到上一历史版本，返回 `merged: true`。普通人工保存追加版本。
- 回滚以目标内容追加新版本。运行目录文件使用冻结的 `edit_base` 走本地评审合并流程。
- 提交成功后发布 `document_content:changed` 元数据事件，包含文档类型、标识与历史版本号，工作区边界由事件传输层补齐。客户端定向刷新正文和版本查询。
- 运行完成与重连也刷新对应文档查询，正在编辑的正文与基准保留。

组件及真实数据库回归覆盖首次编辑、任务元数据变化后保存、刷新后首次保存仍使用原基准、提交后通知和版本差异。真实用户操作链路按 §7.2 记录验收结果。

### 7.4 FR-CHAT-04 浮动选区内联工具栏

- **优先级**：P1
- **行为**：只读正文选中文本后，选区上方 8px 浮出工具栏，提供「加入子任务…」与「添加到对话」。
- **规则**：
  - 仅作用于**只读文本容器**；图片/附件区域不出现。
  - 「加入子任务」以选区文本折叠空白后的前 200 字符为标题，父议题为当前议题。
  - 「添加到对话」把原文交给输入框作为引用，随后清空浏览器选区。
- **验收**：
  1. 附件图片区拖选不出现工具栏。
  2. 子任务标题与父议题正确。
  3. 添加到对话后选区被清空。

### 7.5 FR-CHAT-05 语音输入

- **优先级**：P1
- **规则**：
  - 录音上限 60 秒；转写超时 120 秒；音频 ≤ 512 KiB；转写文本 1..16384 字符。
  - 依次尝试 `webm/opus → webm → mp4 → ogg/opus`，码率 48 kbps。
  - Escape 取消；页面隐藏即取消；取消后编辑器内容与进入前完全一致。
  - 失败提示分四档：需升级服务端/运行时、未配置转写器、运行时离线、录音或转写失败。
- **验收**：
  1. 录音 60 秒自动停止并进入转写。
  2. 按 Escape 后内容不变且不产生转写请求。
  3. 501 时提示「请更新服务端和所选运行时」。

### 7.6 FR-CHAT-06 听写草稿预览

- **优先级**：P1
- **规则**：
  - 转写结果以**不可编辑、不可删除**的预览段落实时追加；结束时转为正常正文。
  - 预览期间 `getMarkdown()` 必须剔除预览段落，避免把未确认语音写进持久化草稿。
  - 预览插入不进入撤销历史，取消后无空行残留。
- **验收**：
  1. 预览期间按 Backspace 无法删除预览段落。
  2. 预览期间草稿不含预览文字。
  3. 一次撤销只移除整段插入。

### 7.7 FR-CHAT-07 输入历史导航

- **优先级**：P2
- **规则**：
  - 光标在文档首按 ↑、在末尾按 ↓，在「本会话自己发过的消息」间翻动。
  - 修饰键按下、输入法组字、选区非空、有未完成上传时**不拦截**。
  - 历史附件保持原消息归属，**不得重新绑定**到新消息。
  - 用户改动载入内容后，再按方向键即重新开始。
- **验收**：
  1. 空输入框连按三次 ↑ 依次出现最近三条自己的消息。
  2. 翻到历史后发送，原附件仍归属原消息。
  3. 最新一条再按 ↓ 清空输入框。

### 7.8 FR-CHAT-08 群组会话

- **优先级**：P1
- **规则**：
  - `ChatPage` 同时提供单 agent 直聊和多 agent 群聊入口；多选 agent 后先写入群会话列表，再进入 lead agent 会话。
  - 参与者只能是 agent；lead agent 标注「群主智能体」。
  - 群名可编辑（Enter 保存 / Escape 取消 / 空值回滚）。
  - 移除成员为乐观删除，失败回滚。
  - 非成员、无作者信息、自己发的消息不显示作者行。
  - 新建群会话必须先写入列表缓存再失效，避免被误判为悬空会话。
- **验收**：
  1. 新建群会话后列表立即可见且不被取消选中。
  2. 移除成员失败后成员重新出现。
  3. direct 会话不显示作者行。

### 7.9 FR-CHAT-09 执行范围收窄

- **优先级**：P1
- **规则**：
  - 按三条关系收窄可选项目/小队：项目 lead、显式 agent 绑定、agent 所属小队绑定。
  - 存在任一收窄关系时，「工作区范围」选项消失。
  - 加载未完成时用全量兜底，避免闪空；请求失败也视为已加载。
  - 已存在的会话直接采用其原有项目/小队，不再过滤。
- **验收**：
  1. 选择只绑定项目 A 的 agent，选择器只出现 A。
  2. 无绑定关系时出现「工作区范围」。
  3. 查询失败时选择器仍可用。

### 7.10 FR-CHAT-10 会话文件面板

- **优先级**：P1
- **规则**：
  - 四个 Tab：文件 / 附件 / 议题 / 群成员；群会话默认「群成员」，普通会话默认「文件」。
  - **议题 Tab 懒加载**，未点击不发请求。
  - 附件 = 会话附件 ∪ 项目附件，按 ID 去重。
  - 目录分页 100 条，读取超时 60 秒；`truncated` 时提示需升级；`has_more` 但偏移未推进时报错防死循环。
  - 目录所属设备离线时提示「请连接此目录所在的设备后重试」，不能伪装成空目录。
- **验收**：
  1. 未点议题 Tab 前无 issue 请求。
  2. 300 个文件首屏 100 条。
  3. 设备离线时显示连接提示而非「暂无文件」。

### 7.11 FR-CHAT-11 文档引用 chip

- **优先级**：P2
- **规则**：引用内容以 `\n\n---\n\n` 拼接在用户输入之前；仅有引用无文字时也可发送；发送后清空引用。
- **验收**：只添加引用即可发送，消息正文以引用开头。

### 7.12 FR-CHAT-12 失败恢复

- **优先级**：P1
- **规则**：
  - 仅白名单原因允许「继续」：超时、运行时离线、运行时恢复、技能包缺失、provider 网络/容量/5xx。
  - 未知原因**一律只给「重试」**，避免暗示可安全续接被毒化的会话。
  - 「重试」把原始用户输入（含附件）回填输入框。
- **验收**：
  1. `timeout` 同时出现「继续」与「重试」。
  2. `provider_auth` 只出现「重试」。
  3. 回填内容与当初提交一致。

### 7.13 FR-CHAT-13 自主执行策略

- **优先级**：P2
- **规则**：可选时长上限为整数秒且 ≤ 86400，0 表示不限；切换 agent 或草稿槽时清空未受控选择。
- **验收**：选择 3600 后请求体为 3600；90000 被拒。

### 7.14 FR-CHAT-14 附件预览与降级

- **优先级**：P1
- **支持类型**：图片、PDF、视频、音频（可直链）；markdown、html、csv/tsv、json/jsonl/yaml、纯文本（需记录）。
- **判定顺序**：PDF → 视频 → 音频 → 图片 → 非文本则空 → markdown → html → 表格 → 结构化 → 文本。**图片必须先于文本判定**（SVG 也是文本类）。
- **降级链**：同 runtime 本地直读 → 签名下载链接 → 站点相对路径 → 字节流 object URL → 认证下载元数据 → **强制下载**。
- **规则**：
  - 文本类预览必须有附件记录；服务端上限 2 MB，超限 413，非白名单 415。
  - HTML 预览 iframe 只允许脚本，不允许同源与顶层跳转。
  - **预览打不开必定触发下载**，绝不静默无响应。
- **验收**：
  1. 签名过期后图片改用 object URL 显示。
  2. 2.1 MB 文本返回 413。
  3. 所有预览通道失败时点击触发下载。

## 8. 议题与工作进度（ISS）

### 8.1 FR-ISS-01 工作进度面板

- **优先级**：P0
- **行为**：议题页底部汇总「谁在等什么、为什么卡住、下一步该谁做」，并提供动作按钮。
- **规则**：
  - 汇总区分：已完成 / 已结束未完成 / 未结束；支持「直接子任务」与「剩余工作」切换（写入 URL）。
  - 八个筛选：全部、明确阻塞、检查收尾、需要跟进、就绪未分配、待智能体、待其他成员、待前置条件。
  - 每条展示关注原因（27 种均有文案）、负责人、运行状态、归属路径。
  - 九类动作：继续处理、检查并继续、补充信息、检查交付、重新运行、分配负责人、处理运行环境、处理前置任务、提交我的进展。
  - 动作携带议题版本、运行 ID 与幂等键；打开面板时快照版本，版本变化即禁用提交并提示「任务已变化」，输入保留。
  - 面板加载失败**不阻塞**议题正文与评论。
- **验收**：
  1. 版本变化后提交按钮禁用且输入保留。
  2. 两个缺失字段必须都填才能提交。
  3. 连点两次只产生一个任务。
  4. 统计不完整时明确提示「数量不能证明任务已完成」。

### 8.2 FR-ISS-02 目标模式

- **优先级**：P2
- **规则**：
  - 为议题设目标；只有负责人可「确认已完成目标」，之后才进入审核。
  - 未启用时显示输入框；目标为空时「启用」禁用。
  - 查询 404 视为未启用（静默展示表单），其他错误不打扰页面。
- **验收**：非负责人看不到完成按钮；已完成后不再显示关闭。

### 8.3 FR-ISS-03 需求生命周期

- **优先级**：P2
- **规则**：需求类议题有 R 标记与三态（待确认 / 已确认 / 变更待确认）；编辑已确认需求后 best-effort 打回「变更待确认」。
- **验收**：reopen 接口失败时正文仍保存成功且无报错。

### 8.4 FR-ISS-04 人机请求卡片

- **优先级**：P0
- **类型**：确认、选择、输入、手工步骤。
- **规则**：
  - 可操作 = 待处理 且 未过期 且 有回答权 且 类型已知。
  - 选择类选项带 `A.` 与 `1.` 双前缀，推荐项高亮。
  - 输入类 ≤ 2000 字符；请求体 ≤ 12 KiB。
  - 服务端二次校验：机器凭据不能回答；回答者必须是指定接收人；版本变化返回 409。
  - 渠道必须一致（会话/评论/项目）。
  - 已答显示所选标签。
- **验收**：
  1. 过期卡片所有按钮不可点，且不显示「等待他人」。
  2. 无回答权显示「等待指定成员处理」。
  3. 提交后立即变为已答并显示选项标签。

### 8.5 FR-ISS-05 文本回复绑定

- **优先级**：P1
- **行为**：存在「可对话回答」的请求时，把普通消息发送转成答复请求。
- **规则（拦截链）**：
  1. 未启用绑定或选「普通消息」→ 正常发送。
  2. 多候选未选目标 → 要求先选。
  3. 与快照同文本但已 stale → 拦截。
  4. 有候选但文本不匹配 → **拦截**（`reply_no_match`），不发普通消息。
  5. 过期或无范围 → 拦截。
  6. 成功 → 回写缓存并清空输入。
- **匹配**：精确标签、字母序号、数字序号、「第 N 项」；仅 `chat_or_card` 模式可匹配；多义则不匹配。
- **验收**：
  1. 输入无关文本被拦截。
  2. 输入 `A` 命中第一项。
  3. 两个请求都含 `B` 时要求先选目标。
  4. 点选项按钮直接提交后输入框清空。

### 8.6 FR-ISS-06 未读视图

- **优先级**：P0
- **规则**：
  - 未读 = 服务端返回的本工作区未读议题 ID 集合；视图查询带 `unreadFilter`，列表请求注入排序后的 ID。
  - **未解析时不得渲染「无结果」，也不得发出空筛选请求**。
  - WS 事件 `issue_unread:changed` 触发刷新；刷新必须**先取消在途请求再失效**。
  - 未读缓存键**刻意独立于议题缓存**，避免大范围失效把它打掉。
  - 打开议题清未读；「标记为未读」不会在查看期间被自我撤销；应用在后台不清。
  - 未读默认不加入侧栏星标（opt-in）。
- **验收**：
  1. 未读为 0 时显示 `0` 且展开为空。
  2. 未解析时不显示「无结果」。
  3. 另一标签页标记未读后本页 2 秒内 +1。
  4. 后台打开议题不清未读。

### 8.7 FR-ISS-07 协作关系图

- **优先级**：P2
- **规则**：
  - 展示委派/重试/重跑/父子关系；边宽表示任务数；实线未完成、虚线已结束、点线来源不完整。
  - 缩放 0.2×–2×；节点可键盘聚焦。
  - 覆盖不完整时顶部提示并列出原因，**不假装完整**。
  - 默认只看活跃任务，边数 ≤ 20，可展开。
  - 证据抽屉支持按议题分组递归与附件下载，禁止无限递归。
- **验收**：
  1. 缩放到 0.1 停在 0.2。
  2. `coverage=partial` 时出现提示条。
  3. 递归第二层不再出现「来源」入口。

## 9. 本地评审与本地 MR（MR）

### 9.0 定位

在 runtime 本地仓库完成「看 diff → 暂存 → 提交 → 评审 → 选择性合并 → 合并发布」，不依赖 GitHub 等远端平台。**服务端不持久化 diff、快照、审批历史**。

### 9.1 FR-MR-01 三入口与 fail-closed 探测

- **优先级**：P0
- **入口**：议题关联 worktree、agent 的 Work 标签页、桌面端 worktree 管理。Settings > Code 不重复渲染 worktree 总览。
- **规则**：
  - 在确认至少一个 Git 仓库存在前，入口**禁用**。
  - 三种反馈必须区分：检查中 / 确认为空 / 验证失败（可重新检查）。
  - 历史工作目录只是**候选**，不能作为仓库存在的证据。
  - 运行选择器只含「已验证且含仓库」的运行；同一 runtime 下仓库集合相同的运行折叠为最新一条。
  - 探测每 30 秒刷新，失败不重试。
- **验收**：
  1. 未探测完成前按钮禁用并显示「正在验证仓库…」。
  2. 无仓库时显示「无可审查的 Git 仓库」且无按钮。
  3. 探测失败出现「重新检查」。

### 9.2 FR-MR-02 快照与版本身份

- **优先级**：P0
- **规则**：
  - 快照 ID 由路径/分支/目标/HEAD/目标 HEAD/状态与每文件补丁计算摘要；版本 ID 同构。
  - 读请求必须区分场景：只读文件类不需要目标；除索引/清单类必须带版本 ID。
  - 分页上限 500（内容类可到 65536）；文本全文分页 16384 字节。
  - 版本过期返回 409；版本不属于同仓库/目标返回 403。
  - Git 命令统一禁用 pager / hooks / fsmonitor，禁止交互，路径按字面处理，30 秒超时，输出上限 8 MB。
  - 校验时禁用 clean/process filter，避免评审触发用户自定义转换。
- **验收**：
  1. `limit: 501` 的非内容请求被拒。
  2. 旧版本 ID 读取返回 `review version expired`。
  3. 符号链接指向仓库外时读取被拒。
  4. 含 NUL 的文件显示为 `Binary file SHA256: …`。

### 9.3 FR-MR-03 决策状态机与幂等

- **优先级**：P0
- **状态机**：`draft → open → approved | changes_requested → merged`，另有 `merge_recovered`。
- **规则**：
  - 决策必须携带命令 ID，且快照 ID 与版本 ID 一致。
  - 同命令 ID 同载荷重放返回首次结果；不同载荷返回 409。
  - 合并按钮禁用条件：忙碌 / 已合并 / 工作区脏 / 源与目标同分支 / 状态不是 approved。
  - `approve` **只写记录与事件，不接触 Git**。
  - 写盘前再比对一次快照，防止决策期间工作区变化。
  - 操作者由服务端强制为 `local-runtime:<id>`。
- **验收**：
  1. `open` 状态合并按钮禁用。
  2. 同命令重放不产生第二条事件。
  3. `approve` 后 `git status` 与 `git log` 完全不变。

### 9.4 FR-MR-04 暂存区与索引事务

- **优先级**：P1
- **规则**：
  - 索引归 owning runtime 所有；前端只做 `index_id + head + branch + version_id` 乐观并发校验。
  - 暂存/取消暂存路径 ≤ 1000；提交信息非空且 ≤ 8000 字节。
  - 使用独立临时索引文件，提交时原子推进 ref，**不跑 hooks、不签名、不改工作区**。
  - 冲突或不支持的文件不允许入库。
  - 提交需二次确认并点名暂存文件数。
- **验收**：
  1. 过期索引 ID 执行暂存返回冲突而非覆盖。
  2. 提交后 `git log` 新增一条但工作区不变。
  3. 空提交信息被拒。

### 9.5 FR-MR-05 选择性合并

- **优先级**：P1
- **规则**：
  - 只把选中文件在目标分支上重放，生成**单亲提交**；未选文件仍可后续评审，不把整条分支标记为已合并。
  - 前置：能力支持、选择非空、说明非空且 ≤ 8000 字节、工作区非脏。
  - 选择变化后确认态失效，需重新确认。
  - 「全部添加」必须先枚举全部不可变清单页。
  - 冲突返回冲突文件清单，**不清空已选**。
- **验收**：
  1. 只选 1 个文件合并，目标只新增该文件改动。
  2. 其余文件仍可再次合并。
  3. 工作区脏时禁止合并。
  4. 冲突后选择保留。

### 9.6 FR-MR-06 合并与中断恢复

- **优先级**：P0
- **规则**：
  - 合并前重读快照、比对 ID、检查脏/同分支/无提交/冲突。
  - 首父必须是已批准的 target，防止把任意历史推上去。
  - 通过 `receive-pack` + `updateInstead` + `force-with-lease` 发布，目标被并发推进时**失败而非强推**。
  - 上次中断留下的 prepared 回执在下次合并时自动恢复，不产生重复提交。
- **验收**：
  1. 合并中目标被推进，合并失败且目标未被覆盖。
  2. 合并提交第一父等于批准时的目标 HEAD。
  3. 模拟崩溃后重试得到 `merge_recovered`。

### 9.7 FR-MR-07 安全边界

- **优先级**：P0
- **三条独立校验**：
  1. **路径**：必须在工作区根内，或匹配已绑定的外部目录；逐级校验所有权；符号链接需 `EvalSymlinks` + 本地性检查。
  2. **运行时身份**：Profile 头必须一致，Bearer 常量时间比较，Origin 必须为空；runtime 必须已注册；未注册返回 403。
  3. **随机数**：优先 `randomUUID`，不可用时回退 `getRandomValues`；**两者都缺失则抛错并拒绝下发变更**，绝不生成弱 ID。
- **上限**：请求体 512 KiB；评论 ≤ 8000；命令 ID ≤ 128；路径 ≤ 10000。
- **验收**：
  1. 带 Origin 头返回 401。
  2. 错误 profile 返回 401。
  3. 指向根外的路径被拒。
  4. 删除两种随机源后按钮报错且不发请求。

### 9.8 FR-MR-08 评审不触发清理

- **优先级**：P0
- **规则**：评审是「纯读 + 显式 Git 写」；清理必须由用户单独发起并通过独立门禁。
- **验收**：
  1. 点 Review 时清理调用次数为 0。
  2. 关闭对话框后工作树目录与文件未被删除。

### 9.9 FR-MR-09 服务端不持久化与 relay

- **优先级**：P2
- **规则**：
  - 数据库无 MR 相关表。
  - 跨机场景走进程内短时转发，状态接口只暴露 `active` 布尔，不泄漏 diff。
  - 只读动作可取消：每 owner 最多 32 个并发读，45 秒上限。
- **验收**：
  1. 全新建库执行读/批准/合并后无 MR 表。
  2. relay 状态接口不返回补丁内容。

## 10. Squad 协作协议（SQD）

### 10.1 FR-SQD-01 运营协议注入

- **优先级**：P1
- **规则**：squad 的 briefing 由服务端实时拼装，包含职责 1–5（读议题、@提及委派、记录活动、派发后停止、每次触发重评）、状态所有权分叉、硬规则清单。
- **mention 语法**：必须为 `[@名称](mention://<type>/<UUID>)`。
- **状态所有权**：仅当议题分配给本小队时才拥有状态。
- **验收**：未分配本小队的议题使用「不拥有状态」分支。

### 10.2 FR-SQD-02 硬规则

- **优先级**：P1
- **规则（逐条）**：
  1. **交付闭环，而非只过测试**：证据必须到达用户实际运行的入口；只有孤立测试或孤立 API 通过不算完成。
  2. **锚定版本**：必须记录具体版本（HEAD / 构建号 / 入口哈希），不得用「当前源码」或没有锚点的压缩包。
  3. **上板而非只在评论里**：进度必须反映在议题状态、元数据或清单上；长评论链不是进度。
  4. **闭合评审环**：评审中无主的条目必须重新派发给正确 agent 或升级到指定人，不能悬空。
  5. 另有三条前置：说明检查覆盖范围、共享路径单一写者、停滞重派前先验证前置条件。
- **验收**：briefing 快照测试包含全部硬规则原文。

### 10.3 FR-SQD-03 协作约定图谱

- **优先级**：P2
- **规则**：
  - 关系类型：coordinate / handoff / review / accept；含交付物。
  - 编辑权限 = 工作区管理员或小队创建者；成员少于 2 人时禁用新增。
  - 校验自连、成员不在列表、三元组重复。
  - 保存带 `expected_revision`；冲突时提示「保存未确认，草稿已保留」。
  - 历史版本只读。
- **验收**：非授权用户所有输入禁用；冲突后草稿仍在。

## 11. Jev 决策模型（JEV）

### 11.1 FR-JEV-01 三种来源

- **优先级**：P0
- **规则**：

| 来源 | 执行路径 | 是否起模型进程 | 协议 | 元数据 |
| --- | --- | --- | --- | --- |
| `local` | 本机模型租约端点 + 租约 token | 是 | SystemOne | 模型、revision、设备、配置版本 |
| `remote` | 配置端点 + 从自定义环境拷贝的密钥 | 否 | SystemOne | 模型、来源；**不记端点与密钥** |
| `agent_context` | 复用主 agent provider | 否 | chat 语义 | 只记 agent/session/task |

- **默认**：`agent_context`（避免未经选择就下载模型或外发上下文）。
- **无自动回退**：未知来源直接失败，绝不静默改用其他来源。
- **验收**：
  1. `local` 任务环境必然含 SystemOne 标记且端点为 loopback。
  2. `remote` 缺凭据时任务失败，错误含变量名但**不含值**。
  3. `agent_context` 不产生模型进程。
  4. 未知来源失败且不回退。

### 11.2 FR-JEV-02 工作区配置与快照

- **优先级**：P0
- **规则**：
  - 读需成员；写仅 owner/admin 且**拒绝机器凭据**。
  - 请求体 ≤ 32 KiB，拒绝未知字段。
  - `revision` 乐观锁，冲突 409。
  - 迁移未装时读降级为默认配置、写返回 503（有意的不对称）。
  - 配置在任务入队时**快照**写入任务上下文，之后修改不影响已排队任务。
  - 校验：`agent_context` 禁止任何参数；`local` 模型 ID 必须匹配固定格式与 40 位 revision；`remote` 端点必须 https 且无 userinfo/query/fragment，凭据字段只允许 `JEV_*` 形式的环境变量名；超时 1..300 秒。
- **验收**：
  1. 非管理员写入 403。
  2. 并发写同一 revision 只有一个成功。
  3. 任务入队后改配置，已排队任务配置不变。
  4. 表未迁移时读返回默认、写返回 503。

### 11.3 FR-JEV-03 模型目录与安装状态机

- **优先级**：P0
- **模型**：`Mapika/decider-2b`，固定 revision `533964dae8be954c5b5e19fa4948e48408094c1e`，引擎 `1.8.1`，许可 `apache-2.0`，约 3.5 GB。
- **状态机**：

```
not_installed → queued → downloading(依赖|权重) → verifying
              → installed → starting → ready
旁路终态：failed | interrupted | stopping | stopped
```

- **规则**：
  - 安装状态文件 ≤ 16 KiB，原子替换。
  - 记录为「已安装」但文件校验失败 → `failed`（`verified model files are missing`）。
  - 记录为「下载中/校验中」→ `interrupted`，**必须显式重试**，不自动续传。
  - 下载：仅 `huggingface.co` / `hf.co`，≤ 10 跳；文件以独占方式创建，边写边算哈希；sha256 优先，缺失才用 git blob sha1。
  - 全部下载到临时目录 → 校验 → 原子替换。
  - 上限：≤ 512 个文件、单文件 ≤ 128 GiB、总计 ≤ 128 GiB。
  - 拒绝 `auto_map`（阻断远程代码执行）；仅接受 json/jinja/safetensors 且必须是 basename。
  - 引擎：独立 venv，仅装固定 wheel，只保留必要环境变量白名单。
- **验收**：
  1. 删除权重后状态变 `failed` 而非 `installed`。
  2. 下载中杀进程，重启为 `interrupted` 且不自动开始。
  3. 大小或哈希不符安装失败且不产生安装清单。
  4. 含 `auto_map` 的仓库注册失败。
  5. 第 65 个自定义模型被拒（上限 64）。

### 11.4 FR-JEV-04 设备租约与空闲回收

- **优先级**：P1
- **规则**：
  - 租约只对已安装模型建立；未安装直接报错。
  - 设备切换在存在活跃租约时拒绝（`ErrBusy`），不允许静默切换。
  - 空闲 5 分钟回收进程；释放幂等。
  - 就绪探测每 150 ms，3 分钟超时。
  - 并发上限 4（可配 1..32），每任务调用上限 = 并发 × 32（默认 128）。
- **验收**：
  1. 两个任务占用 cuda 时第三个请求 cpu 被拒。
  2. 空闲 5 分钟后进程被回收。
  3. 第 129 次调用被拒。

### 11.5 FR-JEV-05 任务级 MCP 注入

- **优先级**：P0
- **规则**：
  - 任务开始时按快照配置注入一条任务级 MCP 连接。
  - `local` / `remote` 注入端点、密钥与 SystemOne 标记；`agent_context` 不改任何变量。
  - 启动失败必须释放租约（10 秒超时）。
  - 关闭顺序：先停 MCP 再释放租约。
  - 启动条件：有 agent、有自定义环境、模型非空、provider 支持。
- **验收**：
  1. MCP 启动失败后活跃租约回到 0。
  2. `agent_context` 不改变 agent 环境。
  3. 不支持该 MCP 的 provider 静默不启动，任务仍可运行（**可见性缺口**，见 GAP-05）。

### 11.6 FR-JEV-06 MCP 工具面

- **优先级**：P0
- **工具**：
  - 语义模式：`multica_llm2jev_evaluate` + `verify_completion` + `capabilities`
  - SystemOne 模式：`multica_jev_systemone` + `verify_completion` + `capabilities`
- **协议**：`2024-11-05`，仅 POST，Origin 必须为空；请求 1 MiB / 响应 4 MiB / 每任务 128 次 / 并发 4 / 超时 45 秒。
- **能力协商**：首次调用应取 `capabilities` 获得任务 ID、目标锚点、完成输入 schema 与示例。
- **完成校验**：目标必须包含任一目标锚点；任务 ID 必须匹配，否则返回可重试错误并给出正确字段指引。
- **重试变体**：仅对 HTTP 400 依次尝试 4 种参数形态；429/401/5xx/超时**不得**重试（防重复计费）。
- **失败码**：`completion_task_mismatch`、`completion_goal_mismatch`、`invalid_request`、`provider_invalid_response`、`credential_rejected_or_missing`、`provider_timeout`、`provider_unreachable`、`provider_rate_limited`、`provider_http_error`、`provider_unavailable`、`concurrency_limit_exceeded`、`task_call_limit_exceeded`。
- **脱敏**：错误文本不回显 provider body、URL、密钥。
- **验收**：
  1. 带 Origin 头返回 404。
  2. 错误任务 ID 返回可重试的 mismatch。
  3. 429 时只发一次请求。
  4. provider 返回多余字段判为非法响应。

### 11.7 FR-JEV-07 决策日志

- **优先级**：P1
- **规则**：
  - 每次调用一条记录：工具、来源、模型、revision、配置版本、设备、起止时间、耗时、结果分类（`running/success/error/rejected`）、错误码、输入输出、每次尝试（变体、HTTP 状态、耗时）。
  - 脱敏：token、端点、路径、敏感自定义环境、Jev 端点；键名命中 authorization/cookie/credential/*apikey/*token/*password/*secret 即整值替换。
  - 离线暂存：目录 0700，文件名 `<decisionID>.<running|completed>.json`，原子写。
  - 上报：400/403/404/409 视为不可重试并移入失败目录；其他按退避重试。
  - 服务端按阶段（running=0 / completed=1）单调更新，**终态不会被 running 覆盖**，且禁止跨任务写入。
  - 列表仅 owner/admin；查询词 ≤ 500，支持 `as_of` 固定快照。
- **验收**：
  1. 一次成功调用产生 1 条记录，尝试次数等于请求数。
  2. 已完成的记录再以 running 上报不会回退。
  3. 换任务 ID 上报返回 409。
  4. 日志中不出现任何密钥或端点。

### 11.8 FR-JEV-08 置信度与验证元数据

- **优先级**：P0
- **规则**：
  - 只有 SystemOne 模式可写置信度与概率；语义模式**强制不写**（字段不存在，而非 0）。
  - 概率值域 [0,1]，条目 ≤ 256；满足与不满足之和约为 1。
  - `verified=true` 仅当判定为 satisfied 且目标/标准/证据非空、任务匹配。
  - 不确定视为**未验证**；自主模式下转 `blocked`，注释以 `completion_verification_required:` 开头。
  - 并发校验用单调序列，旧回调不得覆盖新结果。
- **验收**：
  1. `agent_context` 结果 `calibrated=false` 且无置信度字段。
  2. `p=0.5` 判不确定且未验证。
  3. 置信度 1.5 被服务端拒绝。
  4. 自主模式下未通过校验的任务状态为 blocked。

### 11.9 FR-JEV-09 用量记账

- **优先级**：P1
- **规则**：兼容 SystemOne 与 chat 两种用量字段；无用量且可计费时判失败；未知用量标记 unknown，**不写 0**。
- **验收**：同时返回两种字段不重复计费。

## 12. 应用托管与网关（APP）

### 12.1 FR-APP-01 服务目录与关系图

- **优先级**：P1
- **规则**：
  - 应用分 `service` 与 `composition`，按 revision 版本化。
  - 关系类型：`contains`、`depends_on`（条件 healthy/started）、`related`。
  - 图约束：禁跨项目边、自环、重复边；`contains` 只能由组合发出且不带条件；必须无环。
  - 名称 1..120 字符且禁控制字符；描述 ≤ 4096 字节。
  - 更新用 revision 乐观锁，整体校验通过才写入。
  - 执行计划按波次分层；空组合报错。
- **验收**：
  1. 跨项目依赖被拒。
  2. `contains` 带条件被拒。
  3. 并发更新只有一个成功。
  4. 空组合计划报错。

### 12.2 FR-APP-02 实例状态投影

- **优先级**：P0
- **规则**：
  - runtime 非在线或 3 分钟无心跳 → `offline`。
  - 代际未追上 → 启动中或停止中。
  - 观测超 45 秒 → `unknown`。
  - 进程状态映射：准备/启动中 → 启动中；停止中 → 停止中；失败 → 失败；运行且健康（或未配置健康检查）→ 运行中；不健康 → 不健康。
- **验收**：心跳停 3 分钟显示离线而非未知。

### 12.3 FR-APP-03 操作与幂等

- **优先级**：P0
- **动作**：start / stop / restart / publish / unpublish / delete。
- **规则**：
  - 幂等键 1..128；同键不同请求返回冲突。
  - runtime 必须可用且具备 `applications-v1` 能力。
  - 本地目录资源必须同 daemon。
  - 存在 pending 操作时拒绝新操作。
  - `publish` 要求端口 > 0 且实例运行中。
  - 被其他应用占用的服务停止需 `force`。
  - 超时按公式计算（3 小时 + 各步 10 分钟 + 准备 + 健康检查 × 重试）。
  - 取消：未认领的 stop/delete 生成反向恢复命令，其余生成 stop。
- **验收**：
  1. 同幂等键不同动作返回冲突且不产生第二条操作。
  2. 无权停止共享服务返回冲突。
  3. 超时操作标记失败并提示「重连后对账」。

### 12.4 FR-APP-04 删除前置与级联

- **优先级**：P0
- **前置**：revision 匹配、无入边关系、无活跃实例。
- **规则**：不满足时返回冲突并列出阻塞方名称；满足后按「消费者 → 票据 → 步骤 → 操作 → 端点 → 实例 → 关系 → 版本 → 应用」级联；操作历史保留。
- **验收**：有依赖或有运行实例时删除失败并列出原因。

### 12.5 FR-APP-05 网关鉴权

- **优先级**：P0
- **三套独立密钥与受众**：

| 用途 | 受众 | 有效期 | 关键约束 |
| --- | --- | --- | --- |
| 访问 | access | 8 小时 | 成员 ID 非空、必须有 exp |
| 连接授权 | connection | 无 exp | 源实例与代际 ≥1 |
| Peer 转发 | peer | 30 秒 | 请求体摘要 |

- **规则**：
  - 强制 HS256 + 受众匹配 + 必须过期时间。
  - 来源必须是绝对 http(s)，无路径/查询/片段/用户信息；非 https 仅允许 localhost。
  - 服务授权 15 分钟，操作白名单，代际不匹配返回 409。
- **验收**：
  1. 用连接密钥伪造访问令牌失败。
  2. 篡改受众失败。
  3. 过期 1 秒的令牌被拒。

### 12.6 FR-APP-06 启动票据与反向代理

- **优先级**：P0
- **流程**：点击打开 → 校验端点已发布、可见性、实例运行中、网关可用 → 生成一次性票据（仅存哈希，默认 1 分钟）→ 重定向到内部启动路径 → 校验并设置 Cookie（8 小时）→ 303 跳转。
- **规则**：
  - private 应用仅发布者可见。
  - 运行期每 3 秒复核端点版本、令牌过期、成员权限、实例状态；任一失败即撤销。
  - 未鉴权返回 401「请从 Multica 打开此应用以登录」。
  - 请求侧剥离所有内部凭据前缀、内部 Cookie、`X-Multica-*` / `X-Workspace-*` / 身份头；响应侧过滤 Set-Cookie。
- **验收**：
  1. 同一票据二次使用失败。
  2. 非发布者打开 private 应用失败。
  3. 上游收不到任何内部头与 Cookie。
  4. 实例停止后 3 秒内访问失败。

### 12.7 FR-APP-07 隧道与集群

- **优先级**：P1
- **规则**：
  - 每 runtime 最多 128 条流；附加等待 15 秒。
  - 读限制 64 KiB，写分 32 KiB 帧；ping 15 秒、读超时 45 秒。
  - 集群租约 45 秒；节点宕机后流量不再路由到该节点。
  - 撤销经 Redis 通道广播。
- **验收**：第 129 条流被拒；节点宕机 45 秒内租约过期。

## 13. 通信与通知（COM）

### 13.1 FR-COM-01 通知机器人

- **优先级**：P1
- **平台**：企业微信、飞书、钉钉、Slack、Telegram。
- **规则**：
  - 每 5 秒调度：清理 → 入队 → 最多 20 次认领。
  - 入队条件：机器人启用、通知在有效期内（24 小时）、成员仍存在、无既有投递。
  - 认领用 `SKIP LOCKED`，`(bot_id, inbox_id)` 唯一去重。
  - 退避 = 60 × 尝试次数（60/120/180/240/300/360 秒），最多 6 次。
  - 消息裁剪到 1900 字节并保持多字节字符完整。
  - 平台地址必须 https，域名与路径白名单校验；凭据加密存储。
  - 错误不回显 URL 与响应体。
- **验收**：
  1. 同一条通知只投递一次。
  2. 第 6 次失败后不再重试。
  3. 超长消息截断且不乱码。
  4. 错误文本不含 webhook 地址。

### 13.2 FR-COM-02 电话与邮件

- **优先级**：P2
- **规则**：
  - 电话号码 E.164 格式。
  - 幂等：每个键一个 pending 文件（独占创建）+ 不可变回执；pending 为空或损坏即判为「不确定」，**fail closed，不自动重发**。
  - 请求指纹排除凭据字段，便于密钥轮换后安全重试。
  - SMTP 默认 465 隐式 TLS，否则强制 STARTTLS；TLS ≥ 1.2；`DATA` 阶段失败返回「投递未知」，**禁止自动重发**。
- **验收**：
  1. 同键并发发送只发出一次。
  2. 写 pending 后崩溃，重启返回「不确定」而非重发。

### 13.3 FR-COM-03 WeCom 媒体链路

- **优先级**：P1
- **规则**：
  - 下载上限 100 MiB，超时 30 秒；SSRF 守卫拒绝内网、保留段、NAT64/6to4；自行解析并对每个地址判定后连 IP 字面量（防 DNS 重绑定）；重定向 ≤ 5 跳。
  - 流式 AES-CBC 解密：密钥 32 字节，IV 取前 16 字节，尾块 32 字节，分块 256 KiB，逐字节校验填充。
  - 临时文件 0600；POSIX 立即 unlink，Windows 在关闭时删除。
  - 先写意图台账再上传；台账失败则拒绝上传。
  - 对象键由「会话 + 消息 + 类型 + 序号」哈希确定，天然幂等。
  - 用户文案：「有附件没能收到，麻烦重新发一次」「附件太大」；多附件失败聚合为一条提示。
  - 出站：分片 512 KiB × 100，传输上限 50 MiB，上传上限 20 MiB；并行度 4/3/2；仅 ack 超时重试一次；**发送阶段 ack 超时不重发**。
  - 附件在文本之后独立投递，预算 5 分钟；状态 `delivered / definitely_failed / unknown`，**unknown 不重试**。
- **验收**：
  1. 解析到内网地址被拒且错误不含完整 URL。
  2. 21 MiB 文件在初始化阶段被拒。
  3. 图片超 10 MB 降级为文件发送。
  4. 三个附件两个失败只提示一次。

### 13.4 FR-COM-04 Lark Typing 清理

- **优先级**：P2
- **规则**：
  - 添加表情前必须先落库（含加密凭据快照）；注册失败则不添加。
  - 仅当操作者为应用且 ID 等于安装的 App ID 时才删除。
  - worker 每 30 秒、每次 ≤ 100 行；退避 30 秒–1 小时；单次远端 2 秒。
  - 每工作区最多 1000 个待处理槽位；超限跳过装饰性添加但**不阻塞消息处理**。
  - 全部指示最长 7 天，到期记 `abandoned_at`（可审计的放弃）。
- **验收**：
  1. 台账注册失败不调用 Add。
  2. 第 1001 个被跳过但消息正常处理。
  3. 7 天后不可认领且 `abandoned_at` 非空。

### 13.5 FR-COM-05 频道附件标记

- **优先级**：P2
- **规则**：附件以 Markdown 块嵌入，用 HTML 注释标记附件 ID；文件名中的 `]`、换行需转义；非法 ID 忽略；同一附件只返回一次。
- **验收**：文件名含特殊字符不破坏 Markdown 结构。

### 13.6 FR-COM-06 绑定页

- **优先级**：P2
- **规则**：通过 `?token=` 兑换绑定；状态机 `idle → redeeming → done | needs-auth | error`；410 过期、409 已被他人绑定、403 非成员；未登录保留 `next`。
- **验收**：同一 token 二次兑换返回 410。

## 14. 桌面端（DSK）

### 14.1 FR-DSK-01 Profile 与端口

- **优先级**：P0
- **规则**：
  - profile 名 `desktop-<host>`；端口 = `19514 + 1 + (字节和 % 1000)`。
  - profile 未解析时**拒绝回退到默认 profile**，所有生命周期操作空转。
  - 端口记录必须同时满足 profile 与 pid 匹配才采用，否则回退哈希端口。
  - 运行中 daemon 的后端地址与目标不一致时，标记 stopped 并失效 profile 缓存。
- **验收**：
  1. 不同主机 profile 与端口不同。
  2. 端口记录被篡改时回退哈希端口。
  3. 未收到 apiUrl 前状态为 stopped 且不读默认 profile。

### 14.2 FR-DSK-02 启动、探测与僵尸回收

- **优先级**：P0
- **规则**：
  - 每 5 秒探测 `/health`（2 秒超时）；恢复场景用 10 秒长探针。
  - 连续 3 次未命中进入确认流程：10 秒长探针 → 读 pid 文件 → 仅「进程不存在」判缺失 → 端口记录二次确认。
  - 无法确认时延迟 3 轮（每轮 30 秒）后交给 CLI 自检。
  - 退避 15 秒 / 30 秒 / 2 分钟 / 10 分钟；30 分钟内 5 次预算；第 6 次进入 `recovery_paused`，需人工启动。
  - 恢复预算按 profile 持久化。过期尝试可清理，已暂停状态需成员显式恢复。
  - 稳定运行 60 秒后清零退避与预算。
  - 认证探针：启动 10 秒仍未就绪才探测；仅 401 或缺 token 判 `auth_expired`，5xx 判未知。
  - 外部托管的 daemon（如 WSL2）禁用自动启停。
- **验收**：
  1. 杀 daemon 后 ≤ 15 秒进入确认流程。
  2. 第 6 次重启被拒并显示暂停。
  3. 服务端 500 时不显示认证过期。
  4. WSL2 场景停止不产生 CLI 调用。

### 14.3 FR-DSK-03 退出流程

- **优先级**：P1
- **规则**：
  - 不自动停止时直接退出，daemon 存活。
  - 自动停止时：暂停轮询 → 停止 → 有活动运行时弹确认 → 停止无法确认时再弹「忽略并退出」。
  - 取消后恢复窗口与状态，且本次不再自动拉起。
  - 强制停止超时 55 秒，普通 15 秒。
- **验收**：
  1. 关闭自动停止后退出不调用 stop。
  2. 有 2 个活动运行时弹窗显示数量。
  3. 选「忽略并退出」后本会话不再自动拉起。

### 14.4 FR-DSK-04 自动更新

- **优先级**：P1
- **规则**：
  - 启动 5 秒首检，之后每小时；自动下载、退出时安装。
  - Windows arm64 用 `latest-arm64` 通道；macOS x64 用 `latest-x64` 且禁止降级。
  - Windows 安装前经 daemon 门禁：有活动任务时二次确认。
  - 退出安装有 10 秒看门狗。
  - macOS 最低系统版本门槛由打包脚本写入。
- **验收**：
  1. 关闭自动更新后定时器被清除。
  2. 有活动任务且用户取消时不会安装。
  3. 低于最低系统版本不展示可安装更新。

### 14.5 FR-DSK-05 版本匹配

- **优先级**：P1
- **规则**：
  - 比较「运行中 daemon 版本」与「将使用的 CLI 版本」。
  - 任一版本未知 → 不重启（fail-safe）。
  - 版本不同且**有活动任务 → 延迟**，空闲才重启。
  - 安装更新前若 `activeTasks > 0` 且不允许打断 → 返回 busy 并携带任务数。
  - 停止后轮询 250 ms 直到进程真正退出（Windows 需释放 exe 锁），默认 15 秒超时。
- **验收**：3 个活动任务时版本不符只延迟，任务归零后下一轮重启。

### 14.6 FR-DSK-06 CLI 引导与下载校验

- **优先级**：P0
- **顺序**：缓存 → 内置 → 托管目录 → 下载安装 → PATH；每个候选都执行 `version --output json` 验证。
- **规则**：
  - 下载必须带校验和；**无校验和即拒绝安装**；哈希不符抛错。
  - 资产名优先 `multica-cli-<v>-<os>-<arch>.<ext>`，必须唯一匹配；否则回落旧命名。
  - 解包用系统 tar，要求归档根目录有二进制；macOS 额外 ad-hoc 签名（失败仅告警）。
  - 已安装且非强制时幂等返回。
- **验收**：
  1. 篡改归档后安装被拒。
  2. 缺校验和拒绝安装。
  3. 多个匹配资产时报错。

### 14.7 FR-DSK-07 白标配置

- **优先级**：P2
生产模式启动时已读取运行配置，并调用应用名称、窗口图标和 macOS Dock 图标适配。开发模式使用工作树隔离名称。
- **规则**：
  - 配置文件 `~/.multica/desktop.json`，含 apiUrl / wsUrl / appUrl / appName / iconPath。
  - 应用名为 1..64 字符。修改运行配置后重启应用加载。
  - 文件缺失 → 静默使用默认云配置；文件损坏 → 显示阻塞错误，**不静默回退**。
- **验收**：
  1. 写入自托管地址后重启生效。
  2. 非法 JSON 显示阻塞错误页。
  3. 应用名 65 字符被拒。

### 14.8 FR-DSK-08 进程总览面板

- **优先级**：P1
- **行为**：展示 daemon、task worker、应用、网关、环境、镜像、MCP、JEV 八类进程的状态、能力、内存、CPU。
- **规则**：
  - 三路数据源各 10 秒轮询。
  - 内存优先取整树值（含子进程），子进程数 > 1 时标注「含子进程」。
  - 总量取去重后的整体足迹，**不等于各行之和**。
  - 仅可停止的行展示停止按钮，且需二次确认。
- **验收**：
  1. 总量与逐行之和可以不相等。
  2. 不可停止的行无按钮。
  3. 未知状态用黄色而非红色。

### 14.9 FR-DSK-09 Worktree 管理

- **优先级**：P1
- **行为**：按业务 agent 分组展示托管工作树，支持筛选、刷新、单条清理与批量清理。
- **规则**：
  - 同名 agent 归一组；不同工作区同名 agent 分开；无本地目录的 agent 不显示。
  - 清理必须先在预览中列出精确路径；未勾选「丢弃改动」不可放弃。
  - 拒绝原因 8 类：active / dirty / unpushed / review / task_* / unowned / output / 空。
  - 评审与清理是两个并列动作，互不触发。
- **验收**：
  1. 分组正确且 stale 排前。
  2. 预览取消后无删除。
  3. 未勾选丢弃时按钮禁用。

### 14.10 FR-DSK-10 标签页、导航与快捷键

- **优先级**：P2
- **规则**：
  - 刷新标签 = 整体重挂载，清空内存态（不保留表单）。
  - Cmd/Ctrl+R 与 F5 被屏蔽；缩放 -3..4.5。
  - 外部链接走 scheme 白名单唯一审计点。
  - 通知仅在主窗口失焦时弹出，去重 1000 条。
- **验收**：
  1. 按 Cmd/Ctrl+R 不刷新。
  2. `javascript:` 链接不打开外部程序。
  3. 窗口聚焦时不弹系统通知。

### 14.11 FR-DSK-11 打包与验收脚本

- **优先级**：P1
- **打包**：
  - 按「目标 × 架构」逐个执行 CLI 打包与 electron-builder；输出到 `dist/<platform>-<arch>`，互不污染。
  - 版本来自 `git describe`；非语义化时生成 `0.0.0-g<hash>`。
  - 无公证凭据时自动关闭公证；无证书时用 ad-hoc。
- **vscreen 验收脚本**：提供 `package / lifecycle / sources / background-input / takeover / input-qualification / performance` 七类场景；GUI 场景需显式允许；远程性能验收要求 ≥ 30 分钟、≥ 30 次循环；缺失覆盖项独立门禁。
- **验收**：
  1. `--mac --x64 --arm64` 产出两个独立目录。
  2. 未允许 GUI 时 GUI 场景直接失败。
  3. 远程配置权限非 0600 时被拒。

## 15. 构建与发布（REL）

### 15.1 FR-REL-01 双通道

- **优先级**：P0
- **规则**：
  - `Fork Images`：tag 触发，发布 backend / web 的 amd64 + arm64 镜像到 GHCR。
  - `Fork Desktop Release`：tag 触发 + 手动派发（须指定 tag ref），构建三平台安装包。
  - 上游 `release.yml` 在 fork 中整体跳过（`if: repository != lsiten/multica`）。
- **验收**：在 fork 上跑上游发布流程时全部 job 被 skip。

### 15.2 FR-REL-02 桌面发布顺序

- **优先级**：P0
- **门禁**：
  - tag 格式 `vX.Y.Z` 或 `vX.Y.Z-<prerelease>`，拒绝 `-dirty`，长度 ≤ 128。
  - 打包前校验打包脚本从 Git 派生的版本与 tag 严格一致。
  - 两个 fork 发布工作流先调用同一提交的 `ci.yml`，强制全量范围。`frontend` 与 `backend` 汇总门禁成功后才输出 `accepted_sha`。
  - 验收脚本校验检出的提交与调用方 SHA 一致，并拒绝缺失、失败、取消、跳过或路径过滤的验收结果。构建按 `accepted_sha` 检出。
  - 三平台全部通过才进入发布。
- **发布**：去重同名资产 → 拒绝调试文件 → **已公开则直接失败** → 创建 draft（可预发布）→ 上传（可覆盖同名）→ 转为公开。
- **失败处理**：上传失败留下可重试 draft；**已公开永不覆盖**；重跑用 Re-run，不移动 tag。
- **验收**：
  1. `v1.2.3-dirty` 校验失败。
  2. 任一平台失败时不出现公开 Release。
  3. 对已公开 Release 重跑报错终止。

### 15.3 FR-REL-03 产物与元数据

- **优先级**：P0
- **矩阵**：macOS（DMG + ZIP）/ Windows（NSIS EXE）/ Linux（AppImage + DEB + RPM），各 x64 与 arm64。
- **命名**：`multica-desktop-<version>-<platform>-<arch>.<ext>`。
- **附带**：每个安装包的 `.blockmap` + 6 个更新元数据文件。
- **保留**：产物与元数据保留 7 天。
- **验收**：每个平台至少一个 `*.yml`；Windows arm64 写入 `latest-arm64.yml`。

### 15.4 FR-REL-04 签名与公证

- **优先级**：P1
- **规则**：
  - 全部可选：无证书仍可产包，但 macOS 自动安装受 Gatekeeper 限制。
  - 无公证凭据自动关闭公证；无证书用 ad-hoc。
  - ad-hoc 时必须对 daemon 与宿主分别以固定标识重签并严格校验，避免每次构建 cdhash 变化导致系统权限失效。
- **验收**：连续两次 ad-hoc 构建的签名标识一致。

### 15.5 FR-REL-05 镜像发布

- **优先级**：P0
- **规则**：
  - 四份构建（backend/web × amd64/arm64）全部成功后才合并 manifest。
  - 打 `<tag>` 与 `sha-<full>` 两个标签；**仅稳定 tag 推进 `latest`**。
  - 构建先通过同提交的全量 CI 验收，再运行部署契约测试。
- **验收**：
  1. manifest 含两个平台。
  2. 预发布 tag 不移动 `latest`。
  3. 只有 3 份成功时不产生 manifest。

## 16. 自托管部署（DEP）

### 16.1 FR-DEP-01 部署形态

- **优先级**：P0
- **规则**：
  - 基础 compose + images 覆盖 = 拉取官方镜像；另有 build 覆盖用于本机构建。
  - 后端与前端仅绑定 `127.0.0.1`；`pull_policy: always`。
  - 服务：postgres（pgvector）、backend、frontend、可选 TURN。
- **验收**：`make selfhost` 命令行不含 `--build`；后端不对公网监听。

### 16.2 FR-DEP-02 必填与关键环境变量

- **优先级**：P0
- **必填**：`JWT_SECRET` 是唯一 compose 级强制项，缺失直接启动失败。
- **镜像相关**：`MULTICA_BACKEND_IMAGE`、`MULTICA_WEB_IMAGE`、`MULTICA_IMAGE_TAG`。
- **地址相关**：`FRONTEND_ORIGIN`、`MULTICA_APP_URL`、`MULTICA_PUBLIC_URL`。
- **不可更换**：`MULTICA_NOTIFICATION_SECRET_KEY`（更换会导致历史通知无法解密）。
- **新增可调项**：
  - 上传清理：开关、保留期（默认 168h，最小 24h）、间隔（默认 1h，最小 1m）、试运行。
  - 应用网关：`MULTICA_APPLICATION_ORIGIN`（空则禁用远程访问）、`MULTICA_APPLICATION_PEER_ORIGIN`（需 Redis 与共享 JWT 密钥）。
- **验收**：注释掉 `JWT_SECRET` 后 compose 配置阶段即报错；保留期 1h 被拒。

### 16.3 FR-DEP-03 升级流程

- **优先级**：P0
- **顺序**：
  1. **备份数据库**。
  2. 显式更新 `.env` 的镜像与地址项（旧值会覆盖默认）。
  3. 拉取并启动（不重建）。
  4. 排障看后端日志。
- **红线**：**禁止 `down -v`**（会删除数据卷）。
- **标签纪律**：先提交工作流变更再打 tag；失败用重跑，不移动 tag。
- **验收**：文档第一条为备份；升级后使用新 tag。

### 16.4 FR-DEP-04 Helm

- **优先级**：P2
- **规则**：
  - 支持内置或外部 Postgres；TURN 可选；双 Ingress（前端 `/` → 3000，后端 `/` → 8080）。
  - Secret 不自建，引用 `existingSecret`。
  - 多副本时迁移用 advisory lock 串行化。
- **验收**：secret 缺失时 Pod 不就绪且错误指向 secret。

## 18. 非功能需求（NFR）

### 18.1 安全

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-SEC-01 | 镜像与控制的像素、输入、文本**永不到达服务端** | 抓包 + 代码审查 |
| NFR-SEC-02 | 所有短期凭证 30 秒过期且可撤销 | 过期用例 |
| NFR-SEC-03 | 敏感操作拒绝机器凭据（Jev 配置、决策日志） | 403 用例 |
| NFR-SEC-04 | 临时文件 0600，POSIX 创建即 unlink | 文件权限检查 |
| NFR-SEC-05 | 子进程可执行文件必须哈希匹配且非符号链接 | 篡改用例 |
| NFR-SEC-06 | 外部媒体下载必须过 SSRF 守卫（含 DNS 重绑定） | 内网地址用例 |
| NFR-SEC-07 | 日志与错误文本不得包含 token、端点、密钥值 | 脱敏断言 |
| NFR-SEC-08 | 应用代理必须剥离全部内部身份头与 Cookie | 上游抓包 |
| NFR-SEC-09 | 随机数不可用时拒绝下发变更，不得降级为弱 ID | 删除随机源用例 |
| NFR-SEC-10 | 路径必须落在已绑定根内，符号链接需解析校验 | 越界用例 |

### 18.2 隐私

| 编号 | 要求 |
| --- | --- |
| NFR-PRI-01 | 屏幕像素点对点传输，服务端不落盘、不缓存、不转码 |
| NFR-PRI-02 | 智能体操作记录只保留结构性元数据，不保留截图内容到服务端 |
| NFR-PRI-03 | 观看与控制通知可关闭，但审计仍留痕 |
| NFR-PRI-04 | 决策日志默认保留结构化输入输出，但必须脱敏 |

### 18.3 性能与容量

| 编号 | 指标 | 目标 |
| --- | --- | --- |
| NFR-PERF-01 | 镜像首帧 | ≤ 3 秒（局域网） |
| NFR-PERF-02 | 镜像帧率 | 30 FPS（v2），≥ 15 FPS（v1） |
| NFR-PERF-03 | 镜像内存 | 分块 256 KiB，不随媒体体积线性增长 |
| NFR-PERF-04 | 会话建立 | 30 秒内完成，否则过期 |
| NFR-PERF-05 | 控制输入延迟 | `busy` 立即返回，不排队阻塞 |
| NFR-PERF-06 | 进程总览 | 10 秒轮询，采样失败不阻塞面板 |
| NFR-PERF-07 | 文件面板 | 单页 100 条，60 秒超时 |
| NFR-PERF-08 | 决策日志上报 | 退避 5 秒–5 分钟，不阻塞任务 |

### 18.4 可观测性

| 编号 | 要求 |
| --- | --- |
| NFR-OBS-01 | daemon 六类进程状态、资源、能力可查 |
| NFR-OBS-02 | 镜像会话与观看事件可审计（5 类事件） |
| NFR-OBS-03 | 决策日志可按来源、结果、agent、时间检索 |
| NFR-OBS-04 | 应用操作有完整步骤状态与超时时间 |
| NFR-OBS-05 | 投递失败保留错误码，但错误文本脱敏 |

### 18.5 兼容性

| 编号 | 要求 |
| --- | --- |
| NFR-COMP-01 | 老 daemon 必须被明确识别为「需升级」，不得静默降级 |
| NFR-COMP-02 | v1 镜像路径必须对旧 daemon 保持可用 |
| NFR-COMP-03 | 未知 WS 帧类型静默忽略（向前兼容） |
| NFR-COMP-04 | 未知失败原因回退到通用文案但保留原始码 |
| NFR-COMP-05 | 六语言键集必须对齐（parity 测试守护） |

## 20. 验收矩阵

### 20.1 端到端主链路

| 链路 | 步骤 | 期望 |
| --- | --- | --- |
| 观看 | 打开 runtime → 镜像 → 首帧 | ≤ 3 秒出现画面，状态 streaming |
| 控制 | 开启交互 → 申请授予 → 移动鼠标 | 指针跟随，松开后 5 秒内释放锁 |
| 抢占 | A 拖拽时 B 操作 | B 收到 busy 且不报错，A 松开后 B 成功 |
| 停止 | 紧急停止 | 1 秒内全部输入 denied |
| 代操作 | 选源 → 选 agent → 指令 | 智能体在指定屏幕操作，浮层显示进度 |
| 会话 | 发消息 → 失败 → 重试 | 输入与附件完整回填 |
| 评审 | 打开 MR → 暂存 → 提交 → 批准 → 合并 | 目标分支新增单亲提交，工作区未被清理 |
| 决策 | 配置 local → 任务运行 → 查日志 | 日志含来源、模型、耗时，无密钥 |
| 发布 | 打 tag → 三平台构建 | 24 个资产，Release 公开 |

### 20.2 负向用例

| 场景 | 期望 |
| --- | --- |
| Linux 打开镜像 | 明确「不支持」，不显示空白 |
| 无权限访问镜像端点 | 404，不泄露存在性 |
| 无授予发送输入 | denied，不注入 |
| 几何变化后输入 | stale，不点错位置 |
| 旧 daemon 打开选择性合并 | 提示升级，不发请求 |
| 重复幂等键不同载荷 | 409，不产生第二条记录 |
| 服务端重启后使用旧凭证 | 拒绝，要求重新进入 |
| 目标分支被并发推进 | 合并失败，不强推 |
