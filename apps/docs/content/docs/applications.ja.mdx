title: アプリケーション
description: プロジェクトのサービスを実行し、依存関係を構成してリモートでアクセスします。
---

受信トレイの隣にある**アプリケーション**を開くと、プロジェクト別の一覧、ランタイム別の配置、状態ボードを確認できます。サービスは選択したランタイムのコンピューターで動作し、Multica が管理とリモートアクセスを調整します。

## サービス、構成、インスタンス

管理対象サービスにはプロジェクトリソース、作業ディレクトリ、準備コマンド、起動プログラムと引数、環境変数、任意のポートとヘルスチェックを設定します。外部サービスは既存のポートに接続し、プロセスを管理しません。構成はサービスや別の構成をまとめ、自身ではプロセスを起動しません。

インスタンスはアプリケーションとランタイムの組み合わせです。設定の保存だけでは動作中のインスタンスは変わらず、明示的な再起動が必要です。ページを閉じたり、作成したエージェントの実行が終了したりしてもサービスは停止しません。

## 関係と接続

同一プロジェクト内で、`contains` は子を含め、`depends_on` は起動または正常性を待ち、`related` は起動順を変えずに関連付けます。循環関係は拒否されます。独立した分岐は並列に起動し、必須依存の失敗は下流をブロックします。構成外の依存を起動するには、関係で明示的に許可します。

構成の停止は自身の使用関係を解除し、別の構成や個別起動が使う共有サービスを保護します。強制停止はそれらにも影響する場合があります。既定のランタイムと個別の配置を選択できます。非公開ランタイムは所有者のみが使用でき、ワークスペース管理者も例外ではありません。

`API_URL` などの HTTP 接続には依存関係と接続先ポートが必要です。同一コンピューターではローカルアドレスを使います。別ランタイム間では接続先を公開し、専用ローカルプロキシの URL を注入します。認証情報はサービスプロセスに渡しません。停止、世代の変更、公開解除、アクセス権の撤回で接続が無効になります。

## 公開と監視

起動はサービスを実行し、公開は認証付きの入口を作成します。自動公開は準備完了後に行われます。公開解除はアクセスを取り消し、プロセスは維持します。セルフホストでは、管理画面と異なる専用ワイルドカードドメイン、DNS、TLS を用意し、`MULTICA_APPLICATION_ORIGIN` を設定します。[環境変数](/environment-variables)を参照してください。

Multica から開くと、一度だけ使えるチケットがアプリケーション専用セッションに交換されます。プラットフォームのログイン認証情報は転送されません。HTTP、WebSocket、SSE、アップロード、ダウンロードはランタイムの外向きトンネルを使います。匿名の一般公開は対応していません。

プロセス、正常性、公開状態、接続状態は別々です。ランタイムがオフラインでもサービスの停止は確認できません。操作の各ステップで部分的な失敗を確認します。キャンセルは停止や再開の確認まで `cancelling` のままで、完了済みの分岐や共有サービスを維持します。

ログはカーソルで継続取得でき、一時停止、検索、取得済み内容のダウンロードに対応します。保存量は制限され、欠落表示は古い出力が失われたことを示します。停止後も、ログが残りランタイムに接続できれば確認できます。秘密値はローカル環境変数の参照を使用し、既知の認証情報はマスクします。自動再試行は回数制限付きで任意です。コンピューター再起動後の復元は既定で無効です。削除前にインスタンスを停止し、参照を解除してください。

操作期限には 3 時間の待機猶予と、コード準備、準備コマンド、ヘルスチェック、再試行の予算を含みます。キャンセル後の確認期限は 15 分です。期限切れは操作と古い実行リースを終了し、成功した分岐を維持します。未確認の停止は再接続後に照合し、タイムアウトだけでプロセス終了とは判断しません。ワークスペースを離れると古いセッション、接続認証、チケットは失効し、再参加しても復活しません。新しい認証が必要です。

## CLI とエージェント

デーモンの GC が有効な場合、停止確認済みのログと専用リポジトリーのコピーを 7 日間保持します。削除前に最新の完全なランタイム一覧とローカルプロセスの所有権を確認し、実行中のサービス、共有利用者、未配信の成果、元のプロジェクトディレクトリーを保護します。停止記録は古い世代の指示を拒否するため残します。参加権限の消失を同期で確認すると、そのワークスペースのローカルサービスのみ停止します。

`multica application list`、`get`、`plan`、`status`、`operations`、`logs` を利用できます。`start`、`stop`、`restart`、`publish`、`unpublish` は `--body-file` で `revision`、`runtime_id`、`idempotency_key`、任意の `placements` を指定します。同じキーは同じ操作の再試行に使います。`--wait` のタイムアウトは待機のみを終了し、操作はキャンセルしません。明示的な取消は `cancel <application-id> <operation-id> --wait` です。`logs` は `--instance`、`launch` と `service-access` は `--endpoint` が必要です。

対応するエージェント実行には `multica-applications` MCP サーバーが提供され、カタログ、制御、状態、操作、ログ、サービスアクセスを扱えます。プロジェクトとランタイムの権限は常に適用されます。アクセス認証情報をタスクの報告に含めないでください。
