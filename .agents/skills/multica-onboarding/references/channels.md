# 第三方聊天渠道入口

聊天渠道（例如企业微信、Slack 等）把一个 Workspace 的可连接 Agent 暴露为群聊入口。它不会改变
Agent、Runtime 或 Workspace 的权限边界。具体渠道、字段和安装入口以当前部署的页面为准。

## 通用交互合同

- **群聊是 Agent 对话入口。** 已绑定用户在已连接的群里发送消息，才会进入 Agent 会话。
- **私聊只做账号绑定和绑定状态提示。** 在私聊提出普通任务不会创建 AgentTask。
- 未绑定成员在群聊发消息时，机器人会引用原消息，并提示进入私聊完成绑定；完成后回到群聊继续。
- 引用机器人消息或携带 TID 可续接原会话；否则创建新会话。
- 入站支持的媒体类型（文本、图片、文件、mixed 图文等）和是否支持语音/视频/卡片/增量流式回复，
  以当前渠道文档为准，不要凭记忆假设。
- 不会发送用户可见的“正在处理”回执；最终结果通过原 callback 回复，并在失败时安全降级。

## `/issue`

```text
/issue <标题>
下一行起可填写描述
```

`/issue` 是显式的 Issue 创建入口。同一条消息会设置 `SkipAgentRun`，因此不会再让入口 Agent 对这条
slash command 额外回答一次。不要把普通对话和 `/issue` 同时发送来测试，否则会产生真实 Issue。

复杂任务委派与根 Issue 回流由独立 feature flag 和 Workspace allowlist 控制，默认关闭。基础聊天、
绑定、TID、`/issue` 和 Inbox 不依赖该开关。没有当前配置证据时，不要宣称复杂委派已开放。

## 安装与接入检查（以企业微信为例）

1. Workspace owner/admin 打开 `Settings → Integrations` 下的对应渠道（例如企业微信）。
2. 选择可连接、未归档且准备作为统一入口的 Agent。
3. 录入渠道管理端提供的 BotID 和 Secret。不得把 Secret 发给 Agent、Issue 或群聊。
4. 完成安装并把 Bot 加入测试群；同一个物理 BotID 不能同时绑定多个 Workspace/Agent。
5. 用户点击机器人头像进入私聊，完成 Multica 账号绑定。
6. 回到群聊，以普通、无副作用的问题验证 Agent 对话。
7. 引用机器人消息或携带 TID 验证续接；否则应产生新会话。
8. 只有用户明确要求时才用 `/issue` 验证真实持久工作流。
