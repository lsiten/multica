받은편지함 옆의 **애플리케이션**에서 프로젝트별 목록, 런타임별 배치, 상태 보드를 확인합니다. 서비스는 선택한 런타임의 컴퓨터에서 실행되고 Multica 는 관리와 원격 접근을 조정합니다.

## 서비스, 구성, 인스턴스

관리형 서비스에는 프로젝트 리소스, 작업 디렉터리, 준비 명령, 실행 프로그램과 인수, 환경 변수, 선택적인 포트와 상태 검사를 설정합니다. 외부 서비스는 기존 포트에 연결하며 프로세스를 관리하지 않습니다. 구성은 서비스나 다른 구성을 묶고 자체 프로세스를 실행하지 않습니다.

인스턴스는 특정 런타임에서 실행하는 애플리케이션입니다. 설정을 저장해도 실행 중인 인스턴스는 바뀌지 않으므로 명시적으로 다시 시작해야 합니다. 페이지를 닫거나 애플리케이션을 만든 에이전트 실행이 끝나도 서비스는 자동으로 종료되지 않습니다.

## 관계와 연결

같은 프로젝트 안에서 `contains` 는 하위 항목을 포함하고, `depends_on` 은 시작 또는 정상 상태를 기다리며, `related` 는 실행 순서에 영향 없이 연결합니다. 순환 관계는 거부됩니다. 독립 분기는 병렬로 시작하며 필수 의존성 실패는 하위 서비스를 차단합니다. 구성 밖의 의존성을 함께 시작하려면 관계에서 명시적으로 허용해야 합니다.

구성을 중지하면 해당 사용 관계를 해제하고 다른 구성이나 독립 실행이 사용하는 공유 서비스를 보호합니다. 강제 중지는 다른 사용 항목에도 영향을 줄 수 있습니다. 기본 런타임과 개별 배치를 선택할 수 있습니다. 비공개 런타임은 소유자만 사용하며 워크스페이스 관리자도 예외가 아닙니다.

`API_URL` 같은 HTTP 연결에는 의존 관계와 대상 포트가 필요합니다. 같은 컴퓨터에서는 로컬 주소를 사용합니다. 런타임 간 연결은 대상을 게시한 뒤 전용 로컬 프록시 URL 을 주입하며 인증 정보는 서비스 프로세스에 전달하지 않습니다. 중지, 세대 변경, 게시 취소 또는 런타임 접근 권한 철회로 연결이 무효화됩니다.

## 게시와 상태 확인

시작은 서비스를 실행하고 게시는 인증된 접근 지점을 만듭니다. 자동 게시는 준비 완료 후 실행됩니다. 게시 취소는 접근을 차단하고 프로세스를 유지합니다. 자체 호스팅에서는 관리 도메인과 분리된 전용 와일드카드 도메인, DNS, TLS 를 설정하고 `MULTICA_APPLICATION_ORIGIN` 을 지정합니다. [환경 변수](/environment-variables)를 참고하세요.

Multica 에서 열면 일회용 티켓이 애플리케이션 전용 세션으로 교환됩니다. 플랫폼 로그인 인증 정보는 서비스에 전달되지 않습니다. HTTP, WebSocket, SSE, 업로드, 다운로드는 런타임의 발신 터널을 사용합니다. 익명 공개 공유는 지원하지 않습니다.

프로세스, 상태 검사, 게시, 연결 상태는 별개입니다. 런타임이 오프라인이어도 서비스 종료를 확인할 수는 없습니다. 작업 단계에서 부분 실패를 확인하세요. 취소는 중지나 복구가 확인될 때까지 `cancelling` 상태이며 완료된 분기와 공유 서비스를 보존합니다.

로그는 커서 이어 읽기, 일시 정지, 검색, 불러온 내용 다운로드를 지원합니다. 저장량과 회전은 제한되며 누락 표시는 오래된 출력이 없음을 뜻합니다. 중지 후에도 로그가 보존되고 런타임에 연결할 수 있으면 읽을 수 있습니다. 비밀 값은 로컬 환경 변수 참조로 제공하며 알려진 인증 정보는 가립니다. 자동 재시도는 횟수가 제한되고 선택적으로 활성화합니다. 컴퓨터 재시작 후 복원은 기본적으로 비활성화됩니다. 삭제 전에 인스턴스를 중지하고 참조를 제거하세요.

작업 기한에는 3 시간의 대기 여유와 코드 준비, 준비 명령, 상태 검사, 재시도 예산이 포함됩니다. 취소 후 확인 기한은 15 분입니다. 기한이 지나면 작업과 기존 실행 임대를 종료하고 성공한 분기는 유지합니다. 확인되지 않은 중지는 재연결 후 계속 확인하며 시간 초과만으로 프로세스 종료를 판단하지 않습니다. 워크스페이스를 나가면 기존 세션, 연결 인증, 실행 티켓이 영구적으로 무효화됩니다. 다시 가입해도 복구되지 않으며 새 인증이 필요합니다.

## CLI 와 에이전트

데몬 GC 가 활성화되면 종료 확인된 로그와 전용 저장소 복사본을 7 일간 보관합니다. 정리 전에 최신 전체 런타임 목록과 로컬 프로세스 소유권을 확인하며 실행 중인 서비스, 공유 사용자, 미완료 전달 결과와 원래 프로젝트 디렉터리를 보호합니다. 이전 세대 명령을 거부할 수 있도록 종료 기록은 남깁니다. 동기화에서 멤버십 상실을 확인하면 해당 워크스페이스의 로컬 서비스만 중지합니다.

`multica application list`, `get`, `plan`, `status`, `operations`, `logs` 를 사용할 수 있습니다. `start`, `stop`, `restart`, `publish`, `unpublish` 는 `--body-file` 에 `revision`, `runtime_id`, `idempotency_key` 와 선택적인 `placements` 를 지정합니다. 같은 키는 동일 작업의 재시도에 사용합니다. `--wait` 시간 초과는 기다리기만 끝내고 작업을 취소하지 않습니다. 명시적인 취소는 `cancel <application-id> <operation-id> --wait` 입니다. `logs` 는 `--instance`, `launch` 와 `service-access` 는 `--endpoint` 가 필요합니다.

지원되는 에이전트 실행에는 카탈로그, 제어, 상태, 작업, 로그, 서비스 접근 도구를 가진 `multica-applications` MCP 서버가 제공됩니다. 프로젝트와 런타임 권한은 계속 적용됩니다. 접근 인증 정보를 태스크 보고에 포함하지 마세요.
