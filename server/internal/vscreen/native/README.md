# Native host contract

The existing `multica internal-vscreen-host` process owns real CGVirtualDisplay objects on its initial OS thread and runs a nonactivating NSApplication event loop. No separate app or network listener is created. The runtime lock lives under the actual OS account's home (`.multica/native-claims`, 0700), resolved with `user.LookupId`; changing provider `HOME` cannot split ownership. The native process retains the RuntimeDisplayClaim through verified disposal or its own exit.

## Parent descriptors

- FD 3: inherited Unix control socket. Four-byte big-endian JSON length, maximum 64 KiB; strict version/build and unknown-field rejection.
- FD 4: private bootstrap pipe containing 32 random capability bytes. `hello` echoes those bytes as JSON `token`, with `version:1` and exact `build` (`version + "/" + commit`). Peer UID and capability are checked.
- FD 5: optional inherited Unix media socket. A new parent sends `hello.media:true` and writes the same 32 raw capability bytes to FD 5. The host validates/authenticates FD 5 only on first capture start. Legacy `media:false` parents never touch FD 5 and get `media_unavailable` for capture. Tokens are never arguments or logs.

After FD 5 authentication, `ReadMediaSample` / `WriteMediaSample` exchange a fixed 120-byte header and an Annex-B access unit capped at 8 MiB. The header contains magic `MVSC`, version, flags, payload length, PTS/duration nanoseconds, geometry revision, display ID, a 16-byte stream ID, and 32-byte native/display epochs. Flags 0/1 mean video/non-IDR or video/IDR; flag 2 is a terminal event (flag 3 is invalid). A terminal carries no Annex-B data, zero PTS/duration, and only one fixed ASCII reason of at most 32 bytes: `closed`, `source_gone`, `permission_denied`, or `capture_unavailable`. Go exposes `Kind: MediaTerminal` and `TerminalReason`; video is the zero-value `MediaVideo`. All multi-byte integers are big-endian. Stream IDs and epochs are represented as hex strings in Go. A source emits its terminal once after the native Close attempt and stops delivering; siblings retain the connection. `capture_unavailable` does not assert successful native quiescence. A broken media transport closes FD5 and wakes all sources through EOF. Consumers must handle terminal frames directly, not poll `capture_status` to discover closure. Writes are serialized separately from control; blocked media has a one-second write deadline and invalidates the media lane rather than growing queues.

## Control operations

`ensure`, `describe`, `quiesce`, `dispose` retain the display lifecycle protocol. `describe`/`quiesce`/`dispose` require the exact full epoch; disposal requires quiescence and capture callback shutdown before releasing the runtime lock. Creation waits for system enumeration before optionally moving only the new display's origin. Disposal polls the fresh system display list: per-ID `CGDisplayIsOnline` remained stale after release. Entries removed between enumeration and metadata readback are omitted.

`sources` requires a validated ResourceKey. `Response.Sources` contains native SourceDescriptor values embedding `protocol.MirrorSourceBinding`, plus display ID/name, pixel dimensions, logical dimensions/origin, backing scale and geometry revision. Own virtual displays are included. Other runtimes in the registry and other hosts' displays with the reserved Multica vendor/model are excluded. Built-in displays are physical; other system displays remain accurately labeled system rather than guessing they are hardware.

`start_capture` requires ResourceKey, exact source epoch, and `CaptureOptions`: a new 32-hex stream ID, catalog `Source`, output width/height/FPS/bitrate, excluded window IDs, cursor option and optional MaxLevelIDC. Defaults are 1600x900/30/4 Mbps. Supported explicit negotiated caps are level 3.1 and 4.0; zero selects VideoToolbox auto level. Output geometry is checked against the requested level and actual SPS must not exceed it. Stream IDs cannot be reused within the host. The selected source never falls back to a primary display.

`stop_capture`, `force_keyframe`, `capture_status` require stream ID, ResourceKey and its exact epoch. `Response.Capture` binds the immutable source to output Layout. Status includes encoder Stats and actual SPS profile/level after a frame has been encoded; an empty value is unknown. Capture startup may use up to two five-second framework waits plus cleanup, so the parent should allow a longer start deadline than ordinary lifecycle calls. Stop reports uncertainty rather than releasing an unconfirmed native barrier.

`Layout` expresses full source points, output pixels, and a centered aspect-fit content rectangle. SCStream explicitly captures the full logical display into that destination rectangle with aspect preservation and black letterboxing. It does not change a physical display's mode. For example, a 1600x900 virtual display can remain intact while an ordinary level-3.1 browser receives 1280x720 output.

## Native ownership and limits

`capture.Open(ctx, Config)` starts only after nonprompting screen-recording preflight. SCStream uses exact display ID, queueDepth 3, no audio or microphone, and only complete screen samples. Native ownership is bounded to one retained pending CVPixelBuffer, two in-flight VideoToolbox frames and three encoded samples. Overflow clears dependent output, waits for an IDR and requests a keyframe. IDRs include SPS/PPS; frame reordering is disabled. Samples crossing into Go are copied owned bytes. Close gates delivery, waits for stop/removal, drains the callback queue, then completes/invalidates VideoToolbox. Errors/timeouts remain unavailable; they do not prove quiescence.

There are no AX/input, application launch, AppClaim input ownership, or window restoration operations here yet. Quiescence currently covers display/capture work, and must be extended before input is introduced. Public support must not be advertised merely because virtual creation or synthetic encoding succeeds. Real SCStream frame acceptance, floating-window exclusion, performance and signed-bundle/TCC attribution remain separate gates.
