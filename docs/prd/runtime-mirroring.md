# PRD：运行时镜像

## 1. 背景

Multica 的本地运行时实际运行在用户的机器上。当前用户可以查看运行时的健康状态、配置与关联智能体，但无法实时了解该机器上正在发生的界面操作。需要为每个运行时提供唯一的屏幕镜像，使有权限的用户能从运行时或绑定智能体进入并查看其主机屏幕。

## 2. 目标

1. 每个运行时拥有且只拥有一个镜像源。
2. 屏幕内容从 daemon 所在主机采集，经 WebRTC 直接发送到观看端；服务端不转发或存储屏幕像素。
3. 用户可从运行时详情打开该运行时的镜像；智能体详情可通过其绑定的 `runtime_id` 打开同一镜像。
4. daemon 支持 macOS、Windows 的原生主显示器捕屏，并能明确反馈系统权限或运行环境限制。

## 3. 非目标

- 不新增工作区级“镜像”导航、镜像列表或独立镜像资源。
- 不支持一个运行时选择多个镜像源、选择窗口、录制、回放、音频采集或远程控制。
- 不在服务端保存视频流、截图、录像或可恢复的屏幕内容。
- 不改变项目、智能体或运行时的现有数据归属关系。

## 4. 用户与核心场景

| 用户 | 场景 | 结果 |
| --- | --- | --- |
| 运行时所有者 | 在运行时详情点击“打开镜像” | 进入该运行时的唯一镜像，看到实时屏幕。 |
| 使用智能体的成员 | 在绑定智能体详情点击“打开运行时镜像” | 跳转到该智能体绑定 runtime 的同一镜像。 |
| 无可用镜像的用户 | runtime 离线、daemon 过旧或主机未授予权限 | 看到可理解且可行动的不可用原因。 |
| 多位获授权观看者 | 同时查看同一 runtime | 每人建立独立 WebRTC 观看连接，但共享同一个 daemon 捕屏源。 |

## 5. 产品信息架构

```
运行时列表
  └─ 运行时详情
       └─ 打开镜像 → /{workspace}/runtimes/{runtimeId}/mirror

智能体详情
  └─ 打开运行时镜像 → /{workspace}/runtimes/{runtimeId}/mirror
```

镜像路由是运行时详情的固定子模块，不形成工作区级镜像列表或独立镜像记录。用户可像固定项目一样，将某个 runtime 的镜像路由固定为个人侧栏快捷入口；该快捷入口仅保存 runtime 镜像路由，不创建第二个镜像或改变其归属。

## 6. 功能需求

### 6.1 镜像入口

- 运行时详情始终显示“打开镜像”入口。
- 智能体详情仅在智能体已绑定运行时且当前用户能访问该 runtime 时显示入口。
- 运行时离线或未声明镜像能力时，入口保留但禁用，并展示原因。
- 运行时列表维持现有“进入运行时详情”的入口，不新增镜像列表。
- 用户可在镜像页将当前 runtime 镜像固定到个人侧栏，也可取消固定；固定项沿用项目固定项的排序、权限校验与失效清理语义。

### 6.2 镜像页面

- 页面显示 runtime 名称、连接状态和实时屏幕区域。
- 状态至少包括：准备连接、正在协商、正在镜像、运行时离线、daemon 不支持、系统屏幕权限被拒绝、WebRTC 连接失败。
- 页面离开、浏览器关闭或连接失败后，观看端释放 PeerConnection；daemon 在没有观看者时停止采集。
- 同一 runtime 同时只保留一个捕屏循环；多个观看者复用该帧源。

### 6.3 daemon 原生捕屏

- daemon 从运行时主机的主显示器采集画面。
- macOS 需要 Screen Recording 授权；Windows 的系统限制必须映射为明确错误。Linux 首版不支持镜像，入口必须明确说明不支持而非尝试采集。
- 初版将截图编码为 JPEG 帧，经 WebRTC DataChannel 分片传输并在浏览器端重组显示；该实现避免服务端视频转发与额外本地媒体编解码依赖。
- daemon 不在磁盘上落地截图，不把帧写入日志，不将帧发送到普通 HTTP API。

### 6.4 WebRTC 与信令

- 浏览器为 offer 方，daemon 为 answer 方。
- 服务端只保存短生命周期的 SDP 信令会话，并通过现有 daemon 控制 WebSocket 将 offer 派发给对应 runtime。
- daemon 使用其现有认证上下文提交 answer；会话过期、runtime 断开或答复不匹配必须失败关闭。
- ICE 使用部署配置提供的 STUN/TURN 服务。自托管部署由管理员配置 TURN 服务及其凭据；缺少有效 TURN 配置时，页面须提示跨 NAT 网络可能无法连接。

## 7. 权限与安全

- 镜像观看权限严格继承 runtime 读取权限；每次创建镜像协商会话都必须校验该权限，daemon 回传 answer 时必须校验 runtime 归属。
- SDP 会话必须绑定 `runtime_id`、发起用户与过期时间，不能被其他用户或 runtime 复用。
- 信令、错误日志与审计事件不得包含屏幕帧、截图内容或认证令牌。
- WebRTC 媒体仅在浏览器与 daemon 间点对点传输；服务端不代理 payload。
- 当首位观看者接入和最后一位观看者离开时，服务端必须向 runtime 所有者发送“正在被观看”/“观看已结束”的系统通知；通知包含 runtime 名称、观看状态与发生时间，但不得包含画面内容。

## 8. 技术方案

```
浏览器镜像页
  ── POST SDP offer ──> 服务端短期信令会话
  <─ GET SDP answer ──  服务端短期信令会话
                            │
                            │ daemon 控制 WebSocket（仅 SDP）
                            ▼
                     daemon / runtime 主机
                       ├─ 原生主屏采集
                       ├─ JPEG 编码与分片
                       └─ WebRTC DataChannel ──────> 浏览器重组与绘制
```

关键约束：一个 runtime 对应一个 `MirrorSource`，其内部维护一个捕屏循环和多个观看者 DataChannel；每个观看者拥有独立 PeerConnection，因此断开某一观看者不会中断其他观看者。

## 9. 验收标准

1. 已绑定且在线的 runtime 可从详情进入镜像页并成功显示 daemon 主屏。
2. 已绑定 runtime 的智能体详情可进入完全相同的镜像路由。
3. 一个 runtime 同时被两个用户观看时，仅启动一个 daemon 捕屏循环，两个用户均获得新帧。
4. 最后一位观看者离开后，daemon 在限定时间内停止捕屏与 WebRTC 资源。
5. 无 runtime、离线 runtime、旧 daemon、无系统捕屏权限、ICE 失败均显示对应状态，且不出现空白页面或无限重试。
6. 非授权用户无法创建信令会话、读取 answer 或让 daemon 为其他 runtime 建立连接。
7. 服务端日志、数据库、对象存储和网络 API 中不出现屏幕帧或录像数据。
8. macOS、Windows 各至少完成一台真实 daemon 主机的捕屏与观看端验收；Linux runtime 明确显示“暂不支持镜像”。
9. 用户固定 runtime 镜像后，侧栏显示一个指向该 runtime 镜像路由的快捷项；runtime 被删除、无权访问或取消固定时，该项按既有固定项目语义移除。

## 10. 已确认约束

1. 镜像观看权限严格继承 runtime 读取权限。
2. 首位观看者接入与最后一位观看者离开时，runtime 所有者必须收到系统通知。
3. 自托管部署由管理员配置 TURN 服务。
4. Linux 首版不支持镜像。
