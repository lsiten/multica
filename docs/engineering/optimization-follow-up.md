## 需求与顶层任务方案调整

目标模式已从产品范围移除，不再作为需求类型、顶层任务拆分或验收门禁。原目标模式
通过 issue 描述、需求文档、子任务进度和人工请求表达的部分，统一回到现有任务/需求模型。

当前模型固定为：

```text
Project       长期目标、范围与资源
Requirement   根级需求文档与确认生命周期
Top-level task 无父级的普通 task
Sub-issue     挂在需求或任务下的交付工作
Run           某个任务的一次智能体执行
```

已落地的边界包括：需求不能挂在其他任务下；`top_level_only` 只返回根级普通 task；
缺少 `kind` 的旧 payload 不显示顶层任务徽标；父链循环检测不再有 10 层上限；项目 API
同时返回全部 issue、叶子任务和未完成父任务的进度统计；需求变更卡可以绑定受影响的
直接子任务集合。

本轮方案已完成以下闭环，不再保留“下一阶段”实现项：

1. 移动端列表、项目关联任务和 CLI 参考统一使用 `kind` 与
   `parent_issue_id` 判断需求、顶级任务和子任务；旧 payload 缺少 `kind` 时不猜测。
2. 项目列表、详情和移动端项目页同时展示全部 issue 数、叶子交付数、叶子完成数和未完成父任务数。
3. 需求变更卡支持在 `affected_issue_ids` 中写入最多 100 个直接子任务，后端按集合执行，Web 与移动端卡片显示精确影响范围；缺省仍兼容旧卡片的全量行为。
4. 服务端锁定需求生命周期：待确认或已编辑需求不能新增子任务；工作进度投影移除目标模式的 `affected_goal_count`，stage 继续只提供顺序提示，dependency 继续作为硬阻塞；既有 `stage_waiting`、`dependency` 和循环检测回归覆盖这条边界。

仍需单独验收的是原生设备交互、跨端实时刷新和真实部署环境；这些属于验证证据，不是本轮需求模型的未实现项。

## 当前源码层已完成的聊天工作区能力

以下项目已经在当前源码中实现，并有定向回归证据：

- 多项目聊天使用独立的 `selected_project_id`，当前项目、关联项目和可用项目分开计算；未选择项目时不会读取 worktree。
- 文件抽屉将项目文件、源码管理、当前附件和项目问题分成独立 Tab；源码管理没有 Git 工作区时显示独立空状态。
- 项目切换会清理搜索、目录展开、Git 上下文、当前文档和操作对话框；失效项目会清空选择并要求重新选择。
- 单一聊天 worktree 会作为初始源码范围，多目录聊天要求明确选择；历史版本源码管理支持版本列表和快照读取。
- 浮动聊天和文档标题都可以拖入桌面顶部 Tab 栏；桌面 TabBar 按聊天会话恢复完整聊天页签。
- 文件创建、移动、回收、恢复具备 pending receipt、重试和稳定身份；移动/恢复更新打开文档路径，回收关闭旧 Tab 但保留草稿。
- 文档、项目执行范围和项目监督编辑器统一使用导航守卫；脏内容、保存中状态和关闭确认语义已通过定向测试。
